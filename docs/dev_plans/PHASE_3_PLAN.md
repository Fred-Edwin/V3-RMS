# Phase 3 — Order Management: Codex Task List

## Feature Overview

**Order lifecycle:** Waiter creates order → system splits into PrepTickets by station (KITCHEN / BARISTA) → Chef/Barista claims ticket → marks Ready → Waiter records payment → order Closed.

**Status derivation:** Order is PENDING until any ticket is claimed (→ IN_PROGRESS). Order is READY only when ALL tickets are READY. Waiter can only record payment when order is READY.

**Modification rule:** Waiter can modify an order only while at least one PrepTicket is still PENDING. Once all tickets are IN_PROGRESS or beyond, modification is blocked (409).

**Daily order numbers:** Reset to #1 per branch per day. Generated atomically inside the create transaction (count today's orders + 1) to prevent duplicates under concurrency.

**Price snapshotting:** `OrderItem.unitPrice` is copied from `MenuItem.price` at order creation — immutable financial record, never recalculated from live menu prices.

**PrepTicket `items` field:** JSON snapshot of only the items for that station. A KITCHEN ticket contains only food items; a BARISTA ticket contains only drink items.

**WebSocket rooms:** `branch:{orgId}:kitchen`, `branch:{orgId}:barista` (station rooms), `user:{userId}` (personal waiter rooms).

**KDS/BDS:** Shared tablet display + personal phone view for Chef/Barista. Both real-time. FullscreenLayout on tablet, single-column on phone.

**FCM:** Push notification to waiter when order is ready. FCM failures are swallowed silently — must never break the mark-ready flow.
