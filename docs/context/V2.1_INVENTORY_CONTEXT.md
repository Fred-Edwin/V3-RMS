## Decisions Made

### Requisition Model: Menu Items (not raw ingredients)
- Branches requisition in **portions** (e.g. "10 Flat Whites"), not raw ingredient quantities (e.g. "0.18kg coffee")
- Store Manager dispatches in portions; system converts to raw ingredient quantities via `IngredientConversion` table
- `IngredientConversion`: `ingredientId` + `menuItemId` + `quantityPerPortion` (e.g. 0.018 kg per Flat White)
- **Rationale:** Managers think in menu items, not raw ingredients; conversions abstract the complexity

### Requisition Cutoff Removed
- Original design had a 6 AM morning cutoff and a "mid-day" toggle
- Removed entirely — managers can submit requisitions at any time
- `isMidDay` field kept in DB/API for historical records but no longer enforced
- Frontend: removed `isPastCutoff`, warning banner, and mid-day toggle UI

### STORE_MANAGER Has No Branch Assignment
- Like DIRECTOR, STORE_MANAGER is org-level (no `organizationId`)
- Manages the Central Kitchen, not a specific branch
- No branch selector shown during account creation

### Stocktake: Record-Only (Stock Correction Not Yet Implemented)
- Current implementation records variance but does NOT automatically correct `BranchStock.currentQty`
- No alerts fired on high variance
- **Known gap** — stock correction + director alert on significant variance is pending

### `prepStation` is on `MenuCategory`, not `MenuItem`
- When assigning stocktake station tabs, must traverse: `BranchStock → menuItem → category → prepStation`
- `BOTH` items default to KITCHEN tab

### Pending / Known Gaps
- Stocktake does not correct branch stock automatically after submission
- No alerts to Director or Manager on high stocktake variance
- `canFulfilQty` shows 0 for all items if no conversion ratios are set up — Store Manager must configure conversions first
- Branch stocktake "Waiter" station has no items by default (no menu items with `prepStation = WAITER` in typical setup)
