## Decisions Made

### Requisition Model: Menu Items (not raw ingredients)
- Branches requisition in **portions** (e.g. "10 Flat Whites"), not raw ingredient quantities (e.g. "0.18kg coffee")
- Store Manager dispatches in portions; system converts to raw ingredient quantities via `IngredientConversion` table
- `IngredientConversion`: `ingredientId` + `menuItemId` + `quantityPerPortion` (e.g. 0.018 kg per Flat White)
- **Rationale:** Managers think in menu items, not raw ingredients; conversions abstract the complexity

### Requisition Cutoff Removed
- Original design had a 6 AM morning cutoff and a "mid-day" toggle
- Removed entirely — managers can submit requisitions at any time
- `isMidDay` field kept in DB/API for historical records but no longer enforced
- Frontend: removed `isPastCutoff`, warning banner, and mid-day toggle UI

### STORE_MANAGER Is Assigned to the CK Organisation
- STORE_MANAGER is assigned to the "Wendo Central Kitchen" org (`isHub: true`)
- `getActiveOrganizations()` filters `isHub: false` — CK org is automatically excluded from all branch tables
- No branch selector shown during account creation (same as DIRECTOR)
- Script to create CK org and assign Store Manager: `backend/src/scripts/seed-ck-org.ts`
  - Idempotent: skips if a hub org already exists
  - Run on production: `docker compose exec api node dist/scripts/seed-ck-org.js`

### Stocktake: Record-Only (Stock Correction Not Yet Implemented)
- Current implementation records variance but does NOT automatically correct `BranchStock.currentQty`
- No alerts fired on high variance
- **Known gap** — stock correction + director alert on significant variance is pending

### `prepStation` is on `MenuCategory`, not `MenuItem`
- When assigning stocktake station tabs, must traverse: `BranchStock → menuItem → category → prepStation`
- `BOTH` items default to KITCHEN tab

## Blockers / Issues

### Resolved
- Prisma migration checksum conflict — resolved by patching `_prisma_migrations` table directly
- STORE_MANAGER 403 on `POST /ingredients` — route was DIRECTOR-only; fixed to include STORE_MANAGER
- Silent modal failure on ingredient creation — added `saveError` state to surface API errors

### Pending / Known Gaps
- `canFulfilQty` shows 0 for all items if no conversion ratios are set up — Store Manager must configure conversions first (by design — onboarding requirement)
- Branch stocktake "Waiter" station has no items by default (no menu items with `prepStation = WAITER` in typical setup)

### Resolved (previously listed as gaps)
- Stocktake DOES correct `BranchStock.currentQty` after submission — `createStocktakeSession` runs a `branchStock.upsert` inside the transaction for every entry
- Director variance alerts ARE implemented — `submitStocktake` fires socket event `inventory:stocktake_variance` + FCM push for any item with >10% variance
- Live Stock page UX improved — summary stat cards, filter tabs (All/Out/Low/In Stock), station grouping (Kitchen/Barista), inline search

## Production Deployment Checklist (When Merging feature/v2.1-inventory → main)

### Step 1 — Merge & Deploy Frontend
```bash
# On local machine
git checkout main
git merge feature/v2.1-inventory
git push origin main
```
Vercel auto-deploys from `main`. Wait for Vercel build to succeed before proceeding.

### Step 2 — Deploy Backend (DigitalOcean)
SSH into the server or run from local via the logs script:
```bash
cd ~/wendo-rms
git pull origin main
docker compose up -d --build api worker
docker compose exec api npx prisma migrate deploy
```
Migration to apply: `20260322072523_add_inventory_v2` — adds all V2.1 models and enums.

### Step 3 — Seed the Central Kitchen Organisation (ONE TIME)
```bash
docker compose exec api node dist/scripts/seed-ck-org.js
```
This creates the "Wendo Central Kitchen" org (`isHub: true`) and assigns the Store Manager account to it.
Safe to re-run — idempotent, skips if hub org already exists.

### Step 4 — Create Staff Accounts (if not already done)
Log in as System Admin → `/app/admin` → create:
- **Store Manager** account (assigned to Wendo Central Kitchen automatically)
- **Branch Manager** accounts for each branch (King'ong'o, Nyeri Town)

### Step 5 — Configure Ingredients & Conversions (Store Manager)
Log in as Store Manager → `/app/store/ingredients`:
1. Add all raw ingredients (name, unit, reorder threshold)
2. For each ingredient, click "Conversions" and map it to every menu item that uses it, with the quantity per portion

This is a prerequisite for `canFulfilQty` to show meaningful values on the dispatch page.

### Step 6 — Verify
- [ ] Director at `/app/admin/inventory` — sees King'ong'o and Nyeri Town in Branch Requisition Status (not CK)
- [ ] Store Manager at `/app/store` — can access all Store pages
- [ ] Branch Manager at `/app/manage/requisitions/new` — all menu items appear (not just stocked items)
- [ ] Branch Manager submits a stocktake — `BranchStock` rows created in DB
