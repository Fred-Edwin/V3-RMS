Currently showing: Flow E — Department Head Assignment, folded into a full Staff page redesign (2 screens: Staff page + Add Staff modal)

Scope note — read before the screens below

Why this is a full Staff page redesign, not just a head-assignment bolt-on

  • The existing Manager Staff page (/app/manage/staff) is a flat list with 5 unlabeled icon buttons per row and no department column at all — StaffDto doesn't even carry departmentTag today.
  • Department head assignment is a department-level fact, not a per-row one — it doesn't fit into the existing row shape without restructuring around departments.
  • Assigning a head changes that person's role to DEPARTMENT_HEAD (their prior role is stashed in previousRole and restored on unassignment) — the UI must show "Department Head · Kitchen" as compound state, not lose what their base job was.
  • Owner-confirmed domain mapping: Waiter→Service, Barista→Barista, Chef→Kitchen or Pastry (not 1:1 by role), Housekeeping + Steward→Housekeeping. Manager and display-screen accounts have no department and land in a real Unassigned group, not hidden.
  • Department membership (not just headship) is now editable from this page — without it, the grouped view has no way to populate itself for existing staff.

Screen 1 of 2

Staff

Branch Manager · Desktop · plain table

  • One continuous table — single header row (Name, Email, Role, Status), plain borders, no colored bands. Deliberately quiet: this is a staff roster, not a report.
  • Departments are a subtle grouping within the rows, not separate colored sections — a small gap, then a plain uppercase label row (e.g. "Kitchen · 4 staff") in muted text, then that department's rows directly beneath it. An Unassigned group closes out the table the same way.
  • The department label row also carries head assignment inline — "Head: Fred Barista [Change]" or "No head assigned [Assign]" — so it lives where the department already is, not in a separate panel, without needing its own visual weight to do so.
  • Clicking anywhere on a staff row opens the right-side drawer in Screen 1b, replacing all 5 of today's inline icon buttons.
  • A department head's Role cell shows their base role plus a small "Dept. Head" tag — reflecting that role actually becomes DEPARTMENT_HEAD in the data, with the base role preserved for display via previousRole.
  • "Add Staff" button replaces the inline creation form — opens the modal in Screen 2.

Screen 1b · opens on row click (Fred Barista selected, above)

Staff Detail Drawer

Branch Manager · Desktop · right-side drawer

  • Reuses the exact drawer pattern already built for HR's Leave review (frontend/app/app/hr/leave/page.tsx — fixed inset-y-0 right-0 max-w-sm panel over a dark scrim), not a new component.
  • Editable fields (name, email, phone, role, department) sit at the top — replacing the separate Edit modal with in-drawer editing.
  • Below a divider: the actions that used to be separate icon buttons, now a vertical list inside the same drawer — Reset Password, Transfer Branch, Deactivate, then Delete visually separated in the danger color at the bottom.
  • Closing the drawer (✕ or clicking the scrim) returns to the table with the row still highlighted, matching the selected-row treatment on Screen 1.

Add Staff

Branch Manager · Desktop · Modal

  • Kept as a centered modal (not the drawer) since it's a creation flow, not tied to an existing row — same modal chrome as before.
  • New field: Department. Not inferred from role (a Chef can be Kitchen or Pastry) — the manager must pick it explicitly.
  • Department options are exactly the 5 fixed tags; no "none" option here — new operational staff should be placed into a department at creation, per the owner's domain mapping.
  • Submitting returns to Screen 1 with the new person appearing directly inside their chosen department's band — no separate confirmation screen.
