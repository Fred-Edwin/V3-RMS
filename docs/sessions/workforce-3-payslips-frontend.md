### Facts from the back-end reports you must honour
- **Send two headers on every payslip read that shows pay:** `x-device-id` (the phone's own random id, 8 to 64 characters, created once and kept) and `x-payslip-unlock` (the token the unlock call returns). A locked list shows no amounts.
- A wrong code is `403 CODE_WRONG` (with `details.waitSeconds` when paused), a missing unlock `403 UNLOCK_REQUIRED`, a pause `429`; **not 401** (the apps read 401 as signed out). The server relocks after 10 minutes idle (8 hour cap); the phone calls **Lock** after 60 seconds in the background and when the person leaves the section. Never explain on screen how phones are recognised.
- Hidden amounts are not in the page when hidden (the preference is per device). No payslip amount is ever put in a notification.
- Version 1 stays readable and is marked "Replaced" when a version 2 exists; the HR phone line comes from the response (`hrContact`); if it is not set, the button says "Ask HR".
- A person on a site not yet on the new payslips: the responses carry a `legacy` marker; show the card that opens the old payslip screen, or the empty state.
- **Casual:** the sheet is found or created by site, department and day (`PUT /sheets/lines` with `siteId`, `departmentId`, `date`, `version`, `idempotencyKey`); day pay is rate × minutes ÷ 480 rounded half up; the head records the last 3 days only and sends only after every shift has ended; a sheet the Branch Manager recorded is the Director's to approve; the cash holder pays and each worker signs a receipt on the head's phone; void before anyone signs, a correction line afterwards.
- Add to `capabilities.ts` the three new capabilities from the back-end report (see `workforce-access.ts`: for example `payslip.read_any`, `p9.generate`, `p9.confirm_format`, `casual.record`, `casual.approve`, `casual.read`: use exactly what the access table defines), and notification wording for the new kinds.
- There is no employer KRA PIN and no leave balance on the A4 payslip (the data does not exist yet): do not draw them.
- The Director's daily "who opened someone else's payslip" count is `GET /payslips/opens`: its screen belongs to Segment 6 (the Needs-you card); do not build it here.
