### Facts from the back-end report you must honour
- Wire names: replies say `organizationId` and `organizationName` where the README says site.
- A save sends only the **rows to set**, not the whole tab. Send `expectedVersion` (company) or `expectedSiteVersion` (site): the highest version number in the scope, as returned by the tab read. A stale save is refused; show it in words and offer to reload.
- A wrong PIN is `403 PIN_INVALID`, not 401 (the apps read 401 as logged out). Five wrong tries in ten minutes lock signing; show the lock in words. Send an `idempotencyKey` with every save so a retry is safe.
- Confirm uses `pendingConfirmations[].versionId` and `scope`. A withdrawn version stays in history as "Withdrawn". Withdraw works only on the newest live version of a scope, before its day.
- History replies are a page object `{ items, total, ... }`. A branch holder naming another site gets 404 on reads and 403 on writes.
- "What it would change" rows are only what the server returns; never invent counts.
- **Not built on the back end** (derive or build on the screen): per-table "applies from" for Statutory (derive from history), the casual-threshold warning on the Casual tab, and the shift-template break table (read it from the rota API).
- Notification delivery belongs to a later slice; the event carries recipients, and pay changes carry no figures.
