# Workforce slice 3 (Attendance) front end: decisions made without the owner

Written 18 Oct 2026 on branch `feat/workforce-3-attendance-frontend`. Each row is a question Paper or the brief left open, what was built, why, and what changing it takes. Nothing here changes what a branch whose switch is off sees or can do. Code: `frontend/features/workforce/attendance/` (clock, board, fixes, switch), the Home cards in `features/workforce/home/`.

| # | Question | Chosen | Why | To change it |
|---|---|---|---|---|
| 1 | The menu has to know whether a branch is switched on, and the Director's screen needs every branch. The API only answered one branch at a time. | One small back-end gap, **S3 `GET /workforce/attendance/switch/sites`** (capability `today.read`): every active branch for a company-wide role, the person's own branch for everyone else. Its own commit `fix(workforce-attendance)`, with route and database tests. On the wire the list is `organizations` (wire names). | One request instead of one per branch; no migration. | Remove the route and ask S1 per branch. |
| 2 | Where does the "is it on for me" answer come from? | Floor staff and department heads ask their own day (C1 `enabled`); roles that read the board ask S3; others ask nothing. Cached two minutes, asked again when the tab comes back. Until it answers, and if it fails, the answer is **off** (nothing new shows). | The brief: nothing new for a branch that is off. | `use-attendance-on.ts`. |
| 3 | Replace `SHOW_SCHEDULE_LINKS`. | Gone. Rows carry `needsAttendance`; the Schedule rows, the new Today board row, a head's Rota and Team today, and the floor-staff Home link show only when the branch is on. This **hides Schedule links for every branch that is off**, which owner decision 25 of the Rota session had made visible to all. | The brief names this rule. | Remove `needsAttendance` from a row. |
| 4 | The floor staff's Home link and the route gate. | The gate opens exactly `/app/workforce` (the Home) for floor staff, the Store Attendant and department heads; every other Workforce page stays desktop-only. On a branch that is off the link is not in the menu and the clock card, week card and board cards all answer "no source", so the page only says nothing needs them. Post-login landings are untouched. | The link has to open; the page must stay empty for an off branch. | `lib/route-access.ts`, `useClockCardData`. |
| 5 | The Today board menu row. | Label "Today board", `/app/workforce/today`, for **HR and the Director only** (and a head, as "Team today", scoped to their own departments by the server). **Owner, 18 Oct 2026: removed for the Branch Manager and Store Manager**, whose Home already is the board; their Home board ends with "See everyone today →" to the full page, and the Late and Not in numbers open it too. The System Admin has no Workforce menu (decision 7 of 1a). | The brief asked for the row; Paper's sidebar has none; for managers it duplicated Home. | `nav-table.ts` (`wf-today` roles), `branch-cards.tsx`. |
| 6 | Wire names. | Types read `organizationId`, `organizationName` (my day's `siteName` arrives as `organizationName`). Requests keep `siteId`. | That is what is on the wire. | One file: `attendance-types.ts`. |
| 7 | Server time. | Every counter and window runs on the server's clock: `offsetMs` from `serverNow`, ticking each second. Dates and times are always Nairobi (`nairobi-clock.ts`), never the phone's zone. | A wrong phone clock must not change what the card says. | `useServerNow`. |
| 8 | The shift-end prompt: when does it appear? | The moment the scheduled end passes on a shift still running (one step ahead of the server), then the page asks the server at once so the leftovers arrive; the server's state wins on the next poll. Polling is every 30 s plus when the tab returns. No push, sound or vibration. | The brief: poll using `headsUpFrom` and `autoCloseAt`. | `phaseOf`. |
| 9 | Leaving early, reasons. | The four server codes (sent home, unwell, emergency, other). "Other" sends the code only; Paper draws no text box. | The API takes a code; Paper draws four lines. | `EARLY_LEAVE_OPTIONS`. |
| 10 | "Clocked out by mistake". | **Not a request** (slice 4). The Undo note says "after two minutes, ask your manager", and after a clock-out the card repeats it. "I worked longer" on a phone-closed shift is words: ask your manager to put it right; no button. | A11 of the back end. | Slice 4. |
| 11 | Stay on. | Four reason lines (as Paper) and an optional "about how long" (15, 30 or 60 minutes) the API already takes. | The API has the estimate. | `STAY_ON_ESTIMATES`. |
| 12 | A waiter with open tables (Paper step 6 draws "Hand over tables" and "Stay on" only). | "Hand over tables" (opens Orders) is the brown button, "Finish now anyway" sits under it, then "Stay on". Leftovers never block finishing (A21). | Paper's two buttons would trap a waiter who has handed nothing over. | `shift-end-prompt.tsx`. |
| 13 | No signal. | A tap is kept in the browser's storage with its own `clientEventId` and the phone's time of the tap, shown as "Saved on this phone", sent when the browser says online and every 20 s, removed once the server answers (a refusal is shown and dropped so it cannot block the rest). If the browser refuses storage the person is told it was not kept. | Proposal 5.2. | `offline-queue.ts`. |
| 14 | Position. | Asked at each tap (8 s, up to 30 s old). Without it the server decides ("You must be at the branch…"); its words show on the card. | Same check as the old clock. | `use-clock-actions.ts`. |
| 15 | Week bars. | Planned bars from the Rota stay; a day with worked time turns green at the hours worked, the footer reads hours so far against planned. Overtime waiting waits for slice 4. | Brief. | `week-worked.ts`. |
| 16 | The shift pill. | Grey with the start before the shift, green with hours on shift, amber from the heads-up until clocked out; nothing when done or when the branch is off. | Chapter 6 step 1 to 3. | `shiftPillOf`. |
| 17 | The board's "On leave today". | A dash and "arrives with Leave". Never an invented number. | Same rule as 1a decision 23. | `kpiCells`. |

| 19 | Buttons on the board. | Shown by the server's table: `today.act` (clock in for someone, today only), `time.fix` (Edit time, Set the real finish), `timesheet.read` (the person's day and lateness).
