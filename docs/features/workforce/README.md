# Workforce

The people who work for Wendo, what they are scheduled for, what they worked, and what they are paid. Being redone from scratch in the design lane (`docs/sessions/design-lane-workforce.md`). Nothing is built yet except the foundation.

**Build status (17 Oct 2026):** slice 0 (foundation: access table, time engine, audit writer, rules store; backend only, no screens) is **merged to main** (PR #86, 6 Oct 2026). Contract: [slice-0-contract.md](slice-0-contract.md) (as built, frozen). Code: `backend/src/modules/workforce/`. **Slice 1a (Hire and the file) back end is built (17 Oct 2026), on branch `feat/workforce-1a-employees`, awaiting the owner's check. The 1a screens are built (17 Oct 2026, branch `feat/workforce-1a-frontend`, awaiting review).** Its README, with the endpoints, the access results and every departure from the draft, is [backend/src/modules/workforce/people/README.md](../../../backend/src/modules/workforce/people/README.md). Slice 1b and slices 2 to 7 not started. A contract was drafted for it on branch `feat/workforce-people` (`slice-1-contract.md`, `handoff-slice-1-backend.md`, never merged). **Owner decision, 17 Oct 2026: that draft is kept as reference only, not as a frozen spec, and deleted when slice 1 ships.**

**How slices run (owner decision, 17 Oct 2026).** No contract session and no parallel back end and front end. Each slice is cut into vertical pieces that fit one session, and each piece runs as one back-end session, then one front-end session, one after the other, the owner checking in between. The back-end session's record is the code, its tests, `DATA_MODEL.md`, `API_CONTRACT.md` and the sub-module README. Before the first front-end session there is one session that builds the shared Workforce UI kit (hover, focus and motion rules, the shared components), so screens do not each invent their own.
