## D1. The documents door and the read model (SD28)

Every numbered document is one row in a read model `workforce_documents` that the issuer writes **in its own transaction** through one function `registerDocument(tx, input)` in `_shared/documents/` (and `withdrawDocument(tx, …)`), so the index can never drift:

`{ companyId, siteId?, kind: 'PAY'|'PS'|'CPS'|'P9'|'TSH'|'LVE'|'WRN'|'CTR', number: 'PS-0987', version, title: 'Payslip', about: 'September 2026', subjectUserId?, signedBy: { id, name, role }, reviewedBy?: { id, name, role, at }, signedAt, method: 'PIN', hashPrefix (10), hash, fileRef, status: 'CURRENT'|'REPLACED'|'WITHDRAWN', replacedByVersion?, replacedAt?, withdrawnAt?, withdrawnByRole?, readCapability, openHref }`.

Registering version 2 marks version 1 `REPLACED` in the same call. A **draft** is never registered (no number, no QR). Callers (existing code to touch once each): payroll publish and summary and register (PAY, `payroll/exports`), payslip publish and correction (PS, `payslips/documents`), casual approval (CPS, `casual/approval`), timesheet month approval (TSH, `timesheets/exports`), P9 generation (`payslips/p9`); later Leave (LVE, Segment 4), Conduct (WRN, Segment 5), People contracts (CTR, if the contract file carries a number; confirm at build). A **migration backfills** every number already issued from its own table (payslips, casual sheets, timesheet months, payroll runs, P9). The **weekly rota (ROT) is not listed**: the rota has no sign step (SD28). Retention 7 years from signing (SD5): after that `status` reads `ARCHIVED` and nothing is deleted.

Visibility is the type's capability, read from the access table (never a new role list): PAY `payroll.read` (HR, Accountant, Director; the System Admin also holds `payroll.read` today, which Paper's visibility table denies: log in the gap list), PS and P9 `payslip.read_any` (HR, Accountant; **not** the Director), CPS `casual.read` (Branch Manager own site, HR, Accountant, Director), TSH `timesheet.read`, LVE `leave.read`, WRN `discipline.read`, CTR `employee.read_sensitive`. A row a person may not read is **not listed and not counted**.

## D3. The verify page, what the QR opens (Chapter 17 step 2)

**Purpose and who.** Anyone holding a printed copy scans the QR and learns whether it is genuine, current and unchanged, **without learning anything about a person or any pay**. Route `/verify/{kind}/{number}?h=` (`kind` is `ps`, `cps`, `p9`, `pay`, `tsh`, later `lve`, `wrn`, `ctr`), outside `app/app`, no shell, phone first (390), works on any width. **Public, no sign-in** (SD25): the middleware's public list gains `/verify`. Signing in adds the signer's name and the **Open** button for a person who may read the document.

**Privacy reasoning (why public, and why it is safe).** A stranger who finds a printed payslip, and a shopkeeper handed a signed sheet, must be able to check it. The page therefore confirms only what is already printed on the copy (type, number, period) plus a verdict, and shows **no** name of an employee, no site, no figure, no head count, no bank, no ID number, no phone. The verdict is given only when the number **and** the hash prefix in the QR match; the prefix (40 bits) cannot be guessed from a sequential number, so the page cannot be used to confirm that a number exists or to list documents. The signer is shown as a **role** and a date (Paper shows the name; SD25 withholds it until sign-in).

**Paper shows (three phones).** Left: dark bar `Wendo RMS · Check a document`; card with a 3 px green left bar, mono `✓ THIS COPY MATCHES THE RECORD` (10/12 `success-fg`), title `Payroll summary PAY-2026-09` (20/26 600), text `September 2026. Signed with a PIN by Anne Muthoni, Accountant, on 19 Oct at 11:05.`; a card with rows Status `Signed, not changed` and Checked `Today 14:30`; brown **Sign in to open the document**; `This page shows no amounts or personal details. Only people allowed to read the document can open it.` Middle: red-bar card `THIS COPY DOES NOT MATCH`, `Casual pay sheet CPS-0318`, `The record says the total is different from the number printed on your copy. Do not pay from this copy.`; outlined **Tell the Branch Manager**; `The check is written in the audit log with the time and the phone it came from.` Right: amber-bar card `SIGNED IN AS {NAME}`, `You cannot read PAY-2026-09`, `It is a payroll statement for the Accountant, HR and the Director. The check on the earlier page still holds.`; outlined **Go to Home**.

**Built outcomes (copy exact).** The page asks `GET /api/v1/verify/:kind/:number?h=` and draws one of:

|---|---|---|---|---|---|
| Genuine, current | `✓ THIS COPY MATCHES THE RECORD`, green | `{Document} {number}` (`Payroll summary PAY-2026-09`) | `{Period}. | Genuine, replaced | `THIS COPY IS GENUINE BUT REPLACED`, amber | `Payslip PS-0987, version 1` | `Replaced by version 2 on 20 Oct 2026. Ask for the new copy and do not use this one.` | Status `Replaced`; Checked | as above |
| Withdrawn or voided | `THIS DOCUMENT WAS WITHDRAWN`, red | `{Document} {number}` | `Withdrawn on {date} by the {Role}. Replaced by {number}.` (only when replaced) | Status `Withdrawn`; Checked | none |

| Too many checks | neutral | `Too many checks` | `Wait a minute, then scan again.` | none | none |

**Never** shown publicly: a total, a difference, which part did not match (Paper's "the record says the total is different" is **not** built; it would reveal that totals matter and what they are), a person, a site, a head count. A draft has no QR and no signature, so there is nothing to check: if its number is typed in, the answer is Not verified.

**Interactions and states.** Loading: a card-shaped skeleton `Checking…`; the result card is `role="status"` and receives focus; no-signal: `No signal. A check needs a connection.` with **Try again**; server error: the kit error with the reference (6b M2 right card). **Tell the {issuer role}** (signed in only; the person must have `me.file`): creates the notification `documentMismatch` (`{Document} {number} was checked on a phone and the printed copy does not match the record. Do not rely on that copy.`) to the issuing role of that site (for CPS the Branch Manager, for PAY and PS the Accountant, for TSH the Branch Manager) **and the Director**, writes `document.mismatch_reported` (SECURITY, flagged), and the button becomes `The {role} has been told.`; for an unknown number the notification goes to the System Admin. The page is `noindex`, `Cache-Control: no-store`, has no third-party script, never echoes the query string, and the `h` value is never shown. Language `en-KE`. Targets 44; works at 320 wide and 200 % type; colour is never the only signal (kicker words carry the verdict).

**Rate limit and recording (SD27).** 30 checks a minute and 300 a day per address (Redis, the platform limiter), then 429 and the table row above; a global breaker answers `Too many checks` for all when more than 600 a minute arrive. Every check increments a counter row in `workforce_document_checks` (`kind`, `number`, `outcome`, `at`, `addressHash`, `deviceLabel`); a **signed-in** check also writes `document.verified` (DOCUMENTS) with the person; a **Not verified** answer for a number that exists writes at most one `document.verify_failed` (SECURITY, flagged) per number per day. Paper says every check "is written in the audit log": built that way for signed-in and failed checks, and as a counter for public good checks (a log row per public scan would let a stranger fill the log).

**Server.** Public `GET /api/v1/verify/:kind/:number?h=` (no `authenticate`, `Cache-Control: no-store`, constant-time hash compare, **the same response time for unknown and wrong hash** by always doing the lookup and the compare) returns `{ outcome, kind, number, documentLabel?, version?, periodLabel?, signedByRole?, signedOn?, replacedByNumber?, replacedByVersion?, replacedOn?, withdrawnOn?, withdrawnByRole?, checkedAt, employerName }` with **no** other fields. Signed-in `GET /workforce/documents/verify/:kind/:number?h=` adds `signedBy: { name, role }`, `canOpen`, `openHref`, `readableBy: [role words]`. `POST /workforce/documents/verify/:kind/:number/report { h, idempotencyKey }`. Hash prefix is the first 10 hex characters of the stored file hash, the value the renderers already put in the QR; a version has its own hash, so a copy of version 1 matches version 1 and reads Replaced.

## X1. Migration and rollout plan (SD1)

1. **Additive migrations only**, one migration file each, committed with the code (never `migrate dev` on production): `workforce_audit_entries` gains `area`, `flagged`, `search_text` (defaults, backfilled by a script that fills `area = 'WORKFORCE'`, computes `flagged` and `search_text` for old rows through the same wording function, without touching `hash`: the trigger refuses updates, so the **new columns are not part of the hashed fields and are written by one guarded migration step** (`allowLedgerEditsInThisTransaction`-style bypass for this single backfill, recorded in the migration) or are kept in a side table `workforce_audit_entry_index` keyed by entry id; the signer PIN lock, the error handler and the Inbox page get the three additive edits of SD1. 6. **Rollback:** switch the site off (cards and badges disappear), nothing is lost: all new tables are additive and read only by the new screens.
