# Segment 1A (Timesheets rework): spec decisions

19 October 2026. Written by the spec session for `1a-timesheets-spec.md`. Each row is a question Paper left open or that production needs answered, my recommendation (already written into the spec), why, and what changing it takes. Rows marked **Owner** came from the owner's own decisions and are repeated only so the spec can point at them. Nothing here is built yet. The owner can change any row; the spec cites rows as D1, D2 and so on.

## Decisions

| # | Question | Choice | Why | What changing it takes |
|---|---|---|---|---|
| D1 | Is "Approve September" blocked while things still need the manager? (review default) | **Blocked.** The button stays visible and clickable. The dialog opens in a blocked state: "Still to decide: 3" in amber, a "Show them" link, the PIN field and the confirm button disabled with the reason "Decide the 3 things first". | Paper step 2 draws the button brown while 3 things need the manager, so it cannot be greyed out. The dialog is where the reason can be explained. | One flag in the approve service (`allowWithOpenItems`) and the dialog state. |
| D2 | What counts as "needs you before approving"? | (a) a day that is an exception and undecided (open shift on a past day, clock-out fix, edited-after-approval); (b) an overtime item still pending; (c) a Report a problem or "clocked out by mistake" request still waiting with the manager. A request already moved up to HR does **not** block; the dialog lists it ("2 requests are with HR"). **Late and an unpaid absence never block**: the Rules decide pay (Paper: "for payroll, nothing to approve"). | A request left open would be locked out the moment the month is approved. Late and absence are facts the system records. | `needs-you.ts` rule list. |
| D3 | Part-approved overtime: how is the part chosen and stored? | "Approve part" opens a stepper under the chips: minus and plus in 5-minute steps, from 5 minutes to the extra minus 5 minutes, starting at half the extra rounded down to 5. Stored as `authorisedMinutes` (what payroll may use) on the `overtime_items` row, status `APPROVED_PART` (new value), `decisionReason` required; the remainder is "not approved" and never deleted. | Paper draws the chip with a value but not how it is picked. Minutes are what payroll reads; a distinct status keeps the screens honest. | Step size and the enum value. |
| D4 | Reason when approving all? | Optional on "Approve all"; required (at least 5 characters) on "Approve part" and "Decline". | Paper: "needed to approve part or decline". | Validator. |
| D5 | Approve before the month has ended? | **No.** The button shows only for a month that has ended (state TO_APPROVE). For the open month it is shown disabled with the reason "October ends on 31 Oct. You can approve from 1 Nov." | An open month still changes every day. Approving would lock days that have not happened. | One date check. |
| D6 | When does a month become "To approve"? | Derived, not stored by a sweep: from 00:00 Nairobi on the day after the last day. Nothing closes by itself (Owner). | No timer is the owner's rule; a derived state cannot drift. | None. |
| D7 | Who approves which site? | `timesheet.close` (renamed in the UI "Approve the month") is held only by the Branch Manager (own branch), the Store Manager (Central Store) and the Director (Head office site only). Removed from HR and the System Admin. `timesheet.reopen` is deleted. The department head loses `timesheet.approve` and `overtime.approve`. HR loses `timesheet.approve` and `overtime.approve` for sites. Accountant, HR, Director and System Admin read. | Owner (design pass 3, review). Head office and Central Store approvers are assumed, not confirmed. | One table, `workforce-access.ts`, plus its test. |
| D8 | The Director has no Timesheets menu link, yet approves Head office. Where? | The Director opens Head office timesheets by the same route (`/app/workforce/timesheets?site=...`) from the Director's "Needs you" Home card (Segment 6) and from Payroll (Segment 2). Until those exist the route works by URL only. Flagged to the owner. | The review says only Branch and Store Managers keep a link; the Director's approval then needs another door. | `nav-table.ts` row for the Director. |
| D9 | Who can export? | New capability `timesheet.export`: Branch Manager, Store Manager (own site), HR, Accountant. Director and System Admin read but do not export. | Paper step 5 names Branch Manager, HR, Accountant. The Director's export is for payroll (Segment 2). | One grant per role. |
| D10 | Does HR still fix a clock in an open month? | HR keeps `time.fix` (slice 3, Attendance screens). The period lock changes: a month in state APPROVED refuses every fix, HR included, with "Month approved. Tell HR" (HR sees "Correct the payslip in Payroll" once Segment 2 exists). The Timesheets screens show Edit time only to the site's manager. | The owner's sentence "the Branch Manager fixes alone" is read as "HR does not have to approve". Removing HR's `time.fix` would break slice 3. | Drop HR's `time.fix` row. |
| D11 | Excusing lateness | No longer an exception or a blocker. The built "excuse" action stays as a quiet outlined **Excuse** button on a late row in the full-month page, only while the Rules' excuse window is open and the month is not approved. | Rules already carry `excuseWindowHours`; removing it would silently change payroll input. Paper draws no button, so this is built beyond Paper. | Delete the button. |
| D12 | Document number | `TSH-` plus 4 digits, issued **at approval** from a database sequence (gaps allowed), one per approved site-month. A draft carries no number ("TSH-draft"). Re-exports of an approved month reuse it. The review's TSH-0019 and Paper's TSH-0009 are sample values. | A number with nothing signed under it would be misleading. The built `reportNumber` is issued at creation, so it changes. | Move the allocation. |
| D13 | Range exports of an approved month | Carry the approved stamp, the signature and QR of the whole month, and an extra line "Extract: 14 to 20 September 2026". Of an unapproved month: the draft stamp and "Range: ...". | The signature attests the month; an extract must say it is one. | Copy and one flag. |
| D14 | Who generates the PDF? | The server (never the browser print). Font Tinos (metric-compatible with Times New Roman) embedded; the screen "Document view" shows the same file. Synchronous up to 200 people and 10 seconds, then a background job with a toast and a Notifications row. | A signed document must be byte-identical for every viewer and verifiable. | Library choice only. |
| D15 | QR payload | `https://<app host>/verify/tsh/TSH-0009?h=<first 10 characters of the document hash>`. The page (Chapter 17) shows the number, site, month, who approved and when, and total hours; never names of staff, never money. A draft has no QR. | Public pages must hold the least. Chapter 17 owns the page; it is a dependency. | Page content. |
| D16 | Pages after one | Page 1 holds whole departments up to 20 people (Paper: Barista 9 + Kitchen 8 = 17 because Pastry 5 would make 22). Later pages hold up to 26 people. A department never splits unless it alone exceeds a page (more than 26): then it continues with the band "BARISTA, continued" and a repeated column header. The rules box and signature never split; if they do not fit they take a last page of their own. Departments run A to Z; people A to Z by surname order shown (display name). | Paper's 20-on-page-1 rule with an answer for the edge cases. | Constants. |
| D17 | Excel for a draft | Same three sheets; cell A1 banner "Working copy, draft, not approved" for a draft and "Working copy of TSH-0009, approved 19 Oct 2026" for an approved month. | Paper: "names the signed document it matches". | Copy. |
| D18 | Open month "so far" | Worked and planned are summed over the days from the 1st to yesterday plus today's shifts already clocked out; today's open shifts are not counted, the caption says "open shifts not counted". It is computed in the read, not stored. | The number must not move every second and must not count work nobody has closed. | Cut-off rule in `so-far.ts`. |
| D19 | One "hours worked" number | Hours worked = the sum of the minutes shown in the Worked column. The same number appears in the KPI, the Approve dialog, the PDF and the Excel total. Whole hours with thousands separators in headings ("5,360 h", rounded half up), minutes in tables ("176:00"). Paper shows 5,356 h on the page and 5,360 h in the dialog and PDF: a Paper error (see the spec's list). | One number, one source. | None. |
| D20 | Default month and URL | The page opens on the oldest month in state TO_APPROVE, else the open month. URL: `?site=&month=2026-09&from=&to=&q=&dept=&view=` (view = needs, late, all). A bad month answers "No timesheet for that month" with a link to the latest. | Deep links from badges and Home cards. | Query names. |
| D21 | The months list page size | 5 per page as drawn, with a small numbered pager "‹ 1 2 ›" under "Showing 5 of 9 months", as the table convention requires. | UI_BUILD_RULES §4a. | One number. |
| D22 | People table page size | 50 per page, the kit pager and rows-per-page (25, 50, 100), as drawn. Sort: department then name A to Z by default (so the screen, PDF and Excel agree); headers sort by Person, Worked, Overtime, Late. Paper shows no sort, so this is beyond Paper. | Table convention. | Config. |
| D23 | Branch Manager on a phone or narrow desktop | Below 1100 px main width: the months list becomes a month picker above the table; Dept and Leave columns hide. Below 768: people become cards (name, status line, worked, overtime). Dialogs and the drawer are full width. Approve works at every width. No phone design exists; built in the same style. | Memory: manager is desktop first, no manager phone designs. | Breakpoints. |
| D24 | Head's note on overtime (review default) | A department head may leave a one-line note (140 characters, once, only while the item is pending) with the new capability `overtime.note` (own department). It shows as the evidence line "Head's note: [name], [role], [note]". If there is none the line reads "Head's note: none". It is never a decision. The head's screen for writing it is not drawn and is **not built in 1A**; the back end and the display are. | Review default; the head's phone is a later session. | Add a small screen later. |
| D25 | Idempotency and two people acting at once | Every write carries the item's `version` (an integer). A stale version answers 409 `CHANGED_UNDERNEATH` and the screen reloads the item with "This changed while you were looking. Check it again." Approve carries an idempotency key; a repeat answers the first result, not an error. | Two managers, a double tap, a flaky phone. | None. |
| D26 | Wrong PIN | 401 with "That PIN is not right." inline, the field clears, focus stays. No lockout and tries are not logged (owner's rule for codes, T8). A manager with no PIN set sees "Set your PIN first" with a link to the existing set-PIN dialog. | Same as slice 4a. | None. |
| D27 | HR and the Accountant on approval | They are told (Notifications row and menu badge), and the Payroll waiting-for-a-site line (Segment 2) reads the approval. The notification names the site and month, never a figure other than hours. | Paper dialog text. | Wording table. |
| D28 | The staff member told about overtime | The person gets a Notifications row: "Your overtime on Sat 12 Sep was approved (0 h 35)" / "approved in part (0 h 20 of 0 h 35)" / "not approved". The reason is shown to the person only for a part or a decline. | Paper: "The person is told your answer." | Wording table. |
| D29 | Approved month and the clock-fix door | Message "This month is approved. Tell HR." (Chapter 9, Report a problem and the Edit time dialog). A request created for a day in an approved month is still stored; it goes to HR directly (not to the manager) with the line "Month approved". | Owner's conflict 2 decision. | `requests-rules.ts`. |
| D30 | Auto-close and its words | The sweep no longer closes anything; escalation to HR after 3 days stays. The built `timesheetCutoff` rule field is left stored but unused and hidden in Rules (1B decides its removal). | Owner: no automatic close. | Delete field in 1B. |
| D31 | Excel helper sheets | Three sheets: Timesheet (one row per person), Daily hours (one row per person per day), Summary (totals by department and the rules used). Real numbers, live SUM formulas in the total row, filters and a frozen header row on every sheet. | Paper step 7 text. | Sheet list. |
| D32 | Audit export | Every export (PDF or Excel, draft or approved) writes an audit entry: who, format, month, range, document number or "draft". The file itself is not stored. | Paper: "each export is recorded in the audit log". | None. |
