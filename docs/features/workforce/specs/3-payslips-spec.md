## 0. Rules that apply to every screen

- **Phone frame.** 390 wide, `PhoneDarkHeader` (back arrow, a mono label in caps, 11/14, 0.08em, `sidebar-fg-item`), then a 16 or 18 px page padding. Tall header (the figure or a title) on the first screen of a section (home, one payslip, history, Casuals today); the thin 42 px bar on a document view and where something is done. Desktop roles see the same screens in one 480 px column inside the shell (as My time). Routes (thin shells): `/app/payslips` (home), `/app/payslips/[id]` (detail, `?v=` for a version), `/app/payslips/[id]/document`, `/app/payslips/history`, `/app/payslips/p9/[year]`, `/app/workforce/casuals` (head), `/app/workforce/casuals/[sheetId]`, `/app/workforce/casuals/[sheetId]/document`. The Menu links: **My payslips** under Me (every role with `me.payslip`), **Casuals** under Team (a head with `casual.record`). The Branch Manager reaches approvals from the Home "Needs you" card and the menu badge (Waiting for you was removed, owner pass 4).
- **Kit first.** Use `PhoneDarkHeader`, `PhoneHero`, `PhoneButton`, `SegmentedControl`, `ChoiceChips`, `StatusTag`, `Callout`, `KeyValueRows`, `Panel`, `PinField`, `WorkforcePinDialog` (first-use set), `InboxRow`, `FormField`, `TimeField`, `ReasonChips`, `UndoToast` (not used: acts here are signed), the states kit (`states.tsx`, `states-copy.ts`), `WorkforceDocument`, `DocumentCanvas`, `signatureName`, `lib/document-palette.ts`. Every name below is from `_shared/index.ts`. **Gap:** the phone frame `phone-screen.tsx` lives inside `timesheets/mine/`; features may not deep-import, so the build moves it to `_shared/components/` and exports it (section 15).
- **Buttons.** One brown button per screen. Paper's double-brown pairs (View payslip with Download PDF outlined) already follow this. Disabled buttons show the reason as text (`neutral-600` 12/16) beneath, never a bare grey button (Paper's grey "Print after approval" and "Download P9 for 2026 · from Jan 2027" are built with their reason line).
- **Money.** Amounts in Geist Mono, thousands separators, no currency sign (the label says KES), two decimals only on the A4 document. Hidden amounts are dots (PD8, S2).
- **Tokens.** Paper's values map to `wds-` tokens: page ground `neutral-50` (#F6F5F3), card `white`, hairline `neutral-200` (#E4E2DE), row hairline `neutral-100` (#EFEBE4), borders `border-strong` (#D2CFC9), text `neutral-950`/`neutral-600`/`text-faint`, primary `primary` (#693C1B), success `success-fg` (#2F6438)/`success-bg` (#EEF4EC), warning box `warning-bg`/`warning-border`/`warning-fg` (#FBF3E4, #EAD3A5, #6B4A0F). **No token:** the dark header brown appears as #2E1806 (steps 30, 34, 36) and #2C1707 (step 31, 34 preview): two browns for one band; build both as the kit's `PhoneDarkHeader` colour (`sidebar-top`) and record the difference; the round eye button fill #4A2F1A (a mix of `sidebar-top` and white); the amber note text #8A5A16 and the corrected-line fill #FCF2E4 (`caramel-600` and `warning-bg` nearest); the taken-off number #8C6230 (`caramel-600`); the viewer ground #47433D (the kit's document ground); the bar amber #D9A65E (`caramel-500`, a token); the amber left border #B5823E (`caramel-600`). Flag them in the parity manifest, do not invent tokens.
- **Locked, loading, error, offline.** Use the states kit by key; the screen words are in each section. A request that fails keeps the page and shows the kit's retry line. Offline shows the "saved marker" only where something was typed (Casuals, S7); everywhere else a payslip screen offline says "No signal. Your payslips need a connection to open." with the retry button (a payslip is never cached unlocked, PD2).
- **Very small phone and large type.** Layouts hold at 320 wide and 200 % font: the hero figure may drop one size (44 to 36, 36 to 30), buttons stack to full width, rows wrap onto two lines with the amount staying right, nothing clips and no horizontal scroll. Targets are at least 44 px (Paper's 42 px eye is 44 with its hit area).

**Exact copy (built).** Notice: as Paper (PD10 keeps it figure-free). Warning title: "This payslip is {Name}, {Role}'s." Body: "If you are not {Name}, {Role}, stop here. Every opening is recorded with the phone and the time. On a phone that is not confirmed, the System Admin is told too." (PD6). Button label is the month of the chosen row ("Open September"); with no row chosen the newest row is chosen. Wrong code: field border `error-fg`, line under the field `That code is not right.` (12/16 `error-fg`), field clears, focus stays. Four digits.", two fields ("Choose a code", "Type it again"), button "Save my code" (the kit's first-use set dialog, PD1); mismatch "The two codes are different."; success continues to the open step.

**Interactions and states.** The field is the kit `PinField` (phone number pad kept): the 4th digit enables the button (calls `onComplete`), **Enter never opens**, only the button does (kit rule). Tapping a locked row chooses it (the button label follows). Opening success: the lock rows become links, the code block collapses, the chosen payslip opens at once (S3) and the list stays unlocked for PD2. Pasting a code is allowed. Hover on pointer devices is the kit tint; focus ring 3 px espresso; the unread dot goes when the notice is opened. Screen reader: the field has an accessible name "Your code, four digits", each locked row reads "September 2026, locked", the wrong-code line is `role="alert"`, the slowed state is `aria-live="polite"`.

**Production adds.** Loading: skeleton rows; no payslips yet: `states-copy` empty "No payslip yet. Your first one appears here when your pay is published." with the old-system card or text of PD12; error: kit error with Try again; offline (see section 0); a payslip not yet published is **not listed at all** (a month appears only when published); the notice's button when already unlocked goes straight to S3; the notice opened on a second phone works the same; a code is never remembered or stored in the page; the code field has `autocomplete="off"` and `inputmode="numeric"`. Wrong code behaviour: PD3 (each try recorded, no lockout, a pause after the 5th wrong, the System Admin and the person told after the 3rd, once per 15 minutes). Unconfirmed phone: PD4 (opens, recorded as unconfirmed, loud push to the person, the System Admin told; no word on the screen about phones). A person whose HR reset the code sees "Choose your code" again. A person with the System Admin role has no payslips: the Menu link is absent and the route answers 404.

**Server.** `GET /workforce/payslips/me` (no unlock needed) returns `{ unlockRequired: true, hasCode, items: [{ id, month, versionNumber, correctedAt?, payDay, paidOn?, status: 'PUBLISHED'|'PAID' }], legacyAvailable }` **with no amounts**. `POST /workforce/payslips/me/unlock` body `{ code, deviceId }` checks the code with the person's PIN, writes the audit try (success or failure, device, `confirmed` flag, never the digits), applies the pause rule, and on success returns `{ unlockToken, expiresAt }` (opaque, bound to person and device, PD2); on failure 401 `CODE_WRONG` with `{ waitSeconds? }`. After the 3rd wrong in 15 minutes it creates the System Admin and person notifications once. `POST /workforce/payslips/me/code` sets a first code (409 if one exists). Every payslip read below requires the `unlockToken` header (else 401 `UNLOCK_REQUIRED`). A request for a payslip that is not the caller's answers **404**.

## 17. Accessibility (all screens)

WCAG 2.1 AA. **Hidden amounts are not in the page and are never read (PD8).** The eye is a toggle button with `aria-pressed`; its change is announced politely. The code field is named, numeric, announces errors with `role="alert"` and the pause with a polite live region. Focus order follows the layout top to bottom; the first focus on a code screen is the field, on a document view the back control; dialogs and drawers trap focus, close on Escape and return focus to the opener; Enter never signs. Targets 44 px. Colour is never the only signal (a corrected line also says "corrected from"; the Paid tag also says "Paid"; the year bar has a text alternative). Contrast: `text-faint` (#847E76) is not used for meaning; locked and zero values carry words. Text may grow to 200 % with no clipping; 320 wide has no horizontal scroll; reduced motion removes the transitions. Documents are tagged PDFs with a text view. Tables are real tables with header cells. Phones: the number pad opens for the code (`inputmode="numeric"`), no autofill of the code.
