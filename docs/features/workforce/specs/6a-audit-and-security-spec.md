## A1. The company Audit log (Chapter 14 step 1)

**Purpose and who.** The one log for every area: who did what, when, and why. Read only, no entry can be edited or deleted. Settings, **Audit log**, `/app/workforce/audit-log`. Seen by the Director (everything), HR, the Accountant, the Branch Manager and Store Manager (own site) and the System Admin (account, security, rules), by the visibility table in A7. Staff and department heads have no log, only A8.

**Paper shows.** Title "Audit log" (28/34 600); sub-line "Company log · every area, every entry is written with the change itself · nobody can edit or delete an entry"; right, outlined button "Export this view". Tabs (step 17.1): **Company log** and **Signed documents**. One filter bar: search box "Search person, document or word" (300 wide), dropdowns **All areas ▾**, **All events ▾**, **All sites ▾**, a date button "20 Sep to 19 Oct ▾" (dark 1 px border when open), **Newest first ▾**. Table (card, 1 px border, ink rule under the header): WHEN (mono, "19 Oct 14:05"), WHO, WHAT (bold title), DETAIL, rows 13/16, padding 13/16, hairline `neutral-100`; a row tinted `#FBF3E4` is flagged ("Payslip opened", "Payslip code wrong 3 times" in `error-fg`). Footer "Showing 10 of 1,284 entries", right "‹ Previous · Page 1 of 143 · Next ›". A right-hand panel (Director only) "WHO LOOKED AT THIS LOG": names with "today 14:10", and the note "Payslip opens show who and when, never how much. The Director reads who opened whose payslip. The System Admin sees the alert when a payslip is opened on an unconfirmed phone (who, when, which phone, never amounts). HR and the Accountant do not see these rows." The date picker is the Inventory range picker (quick picks Today, Yesterday, Last 7 days, Last 30 days, This month, Last month, Pick a date or range; From and To fields; two months; Cancel, Apply; "Later dates can't be picked. The log shows every entry from the first to the last day you choose.").

**Exact copy (built).**

| Where | Words |
|---|---|
| Event menu | All events, People, Time and attendance, Leave, Pay and payroll, Rules, Payslip access, Documents, Conduct, Security and sign-ins, Flagged only |
| Sort | Newest first, Oldest first |
| Footer | `Showing 1 to 50 of 1,284` (SD6), over the cap `Showing 1 to 50 of over 50,000. Narrow the dates to count them.` |

| Titles (examples, from Paper) | Rule changed; Payslip opened; Payslip code wrong 3 times; Payroll published; Payroll approved; Leave approved; Payroll reviewed; Tables confirmed; Timesheets approved; Appeal decided |

Titles and details come from **one pure function** `describeEntry(entry)` on the server, tested like Inventory's `audit-log-describe.ts`, one case per registered action (the registry in `audit-actions.ts` is the list: about 110 codes). The same function words A8. A detail never contains an amount, a code or a PIN. Unknown action: title `Change recorded`, detail the action code (a test fails if a registered code has no wording).

**Interactions and states.** Search as you type (250 ms), no Enter; every filter and the page go in the URL (page, rows per page, search, area, event, site, from, to, flagged, sort); a change of filter returns to page 1; Newest first is the default and sorts on `occurredAt` then `seq`. Row hover tint (fine pointers only); a row is a button that opens A3; focus ring 3 px; Enter or Space opens; Escape closes the drawer and returns focus to the row. **Area, Event and Sites list only what the reader may read** (SD3, SD4): a Branch Manager sees no Sites dropdown (own site fixed); the Event menu lists only readable categories. A reader with no readable category and no own-record right gets the route 404 and no menu row.

**Production adds.** Loading: the states-kit list skeleton, "Still loading. Your work is safe." after 8 s. Empty: `No entries in this month.` (kit row "Audit log"); nothing found: `No entry matches. Widen the dates or clear the filter.` with a **Clear filters** button. Error: `We could not load the log. Opening it was still recorded.` with **Try again** and a reference. Offline: the kit strip `No signal.` and the last page kept greyed. A **very large log**: keyset reading under the hood (`occurredAt desc, seq desc`) with the numbered pager mapped onto it; a jump to page 800 uses an offset scan limited to the date range, so the date range is required beyond page 200 (`Choose dates to go further.`). Date range limits: any range, default last 30 days, never later than today. A **cut-off line** under the footer when the range reaches past 7 years: `Entries older than 7 years are archived.` (SD5). Concurrency: new entries arriving while the page is open show a pill `3 new entries` at the top that reloads page 1 (no jump). Large screens: the table scrolls inside its card at under 1100 px; the phone is not a target (desktop roles only, but a 390 px width still works: rows become two lines, WHEN over WHO, DETAIL under WHAT). Keyboard: `/` focuses search; table is one tab stop into a grid, arrows move rows. Screen reader: the table has a caption "Audit log, {n} entries, page {p}"; each row reads "{when}, {who}, {what}, {detail}, flagged".

**Server.** `GET /workforce/audit/entries` (query: `area`, `event`, `siteId`, `actorId`, `subjectUserId`, `from`, `to` (inclusive days in Nairobi), `flagged`, `q`, `sort`, `page`, `pageSize`). Answer: `{ entries: [{ id, seq, occurredAt, actor: { id, name, role }, channel, area, event, action, title, detail, subject: { type, id, label }, subjectUser?: { id, name }, siteId, siteName, flagged, reason?, deviceLabel?, placeLabel? }], total, totalIsExact, page, pageSize, facets: { areas, events, sites } }`. It reads only the categories and scope from `auditReadScopeOf(subject)` (unit scope = rows whose `siteId` is the reader's; company rows with no site are visible only to `all` scope readers); a category the reader may not read is filtered out in the query, never after (a count must not leak). Every list to a non-own reader writes **one** `audit.log_viewed` per reader per 10 minutes (SD9). Search matches actor name, subject label, document number and the wording (a generated `search_text` column on the entry, indexed with trigram; extend the writer to fill it). Facets for the actor type-ahead: `GET /workforce/audit/actors?q=` (readers only, names with role). Errors: a bad range 400 `RANGE_INVALID`; a category outside the reader's scope in the query answers an empty list (not 403) so scope is not revealed.

## A3. The entry drawer (Chapter 14 step 6 "designed later")

**Purpose.** One row in full: before and after, the reason, the device and the chain proof. Opens from a row, 420 wide from the right (`WorkforceDrawer`), over the table. Designed here from the kit; log it in the parity manifest as beyond Paper.

**Layout and copy.** Header: mono kicker `{AREA} · {EVENT}`, title (the row's title, 18/22 600), `FLAGGED` tag when flagged, close ×. `KeyValueRows`: **When** (`19 Oct 2026, 14:05`), **Who** (`{Name}, {Role}`; for the system `The system`; `Via the assistant` when the channel says so), **Site**, **About** (`{Person}, {Role}` when the entry names a person; never for a payslip opening to a reader who may not see the person, see A7), **Reason** (only when one was given), **Phone** and **Place** (only to readers with the right: the Director and the System Admin; `Android, Nyeri (approximate)`). Panel **What changed**: a two-column Before and After table of field names and values (`Lateness grace · 5 min → 10 min, from 2 Nov`); for entries whose after holds pay figures (payroll entries carry figures by 2B decision E9) the Panel is shown only to readers with `audit.read.pay_run_decide`; payslip opens never carry one. Panel **Proof**: `Entry 4,182`, `Hash 3f9a…c21e`, `Follows 77b0…a8d4`, and the line `Written with the change itself. Nobody can edit or delete it.`; a **Check the chain** button for readers with `audit.verify_chain`.

**States.** Loading skeleton; not found or out of scope: kit error `We could not find that entry.` (404, no hint); the chain check: running `Checking…`, then `Chain intact from entry 1 to 4,182.` (green) or `Entry 4,182 does not match the one before it. The System Admin has been told.` (red, and raises the alert, S1). Focus goes to the close button on open and returns to the row; Escape closes; the drawer traps focus. `GET /workforce/audit/entries/:id` (404 if outside scope) returns the full entry with `before`, `after`, `hash`, `prevHash`, `seq`, `signature` (`PIN` or none) and writes the view entry; `POST /workforce/audit/chain/check { fromSeq, toSeq }` answers `{ ok, checked, firstBadSeq? }` (rate limit 1 a minute per reader; reads at most 200,000 entries a call).

## A4. Export

"Export this view" (outlined, right of the title). Disabled with a reason line under it while loading or when the view has no rows (`Nothing to export.`) or more than 50,000 (`Too many to export. Narrow the dates.`). Click: a toast `Preparing your file…`, then the browser download `Audit-log-2026-09-20-to-2026-10-19.csv` (UTF-8 with BOM, Nairobi times `2026-10-19 14:05`, columns When, Who, Role, Area, Event, What, Detail, Site, Reason, Entry number, Flagged; no hash, no device, no amount). Failure: `Could not export. Try again.` `GET /workforce/audit/export` takes the A1 query, streams the CSV, caps at 50,000, escapes a leading `=`, `+`, `-` or `@` with a quote (spreadsheet injection), and writes `audit.exported` (filters and row count, category `LOG_ACCESS`). Capability: any reader of the log (they export only what they can see).

## A6. The nightly check

A job at 02:00 Nairobi runs `verifyAuditChain` over the last two days and a full check every Sunday. A failure writes the alert `AUDIT_CHAIN_FAILED` (S1) and tells the System Admin and the Director (`The audit chain check found a problem at entry {n}. Nothing was changed.`). It needs the worker running (roadmap item 5).

## A7. Who sees what (Chapter 14 step 5, made exact)

Paper's table, mapped to the categories in `audit.types.ts` and to the access table. The Director's row is "nothing hidden, every view is logged".

| Role | Categories read (scope) | Does not see |
|---|---|---|
| Staff, department head | none; **Activity on my record** only (`audit.read_own`) | any company log |
| Branch Manager, Store Manager | TIME, LEAVE, RULES_OPERATING (own site: unit) | pay, payslip opens, conduct, sign-ins |
| HR Manager | PEOPLE, TIME, LEAVE, PAY_SETUP, PAY_RUN_PREPARE, DISCIPLINE (all) **and RULES_OPERATING, RULES_PAY (added, SD4)** | payslip opens, sign-in and security events, documents of pay |
| Accountant | PAY_RUN_DECIDE, RULES_PAY (all) **and PAY_RUN_PREPARE (added, SD4)** | people events, payslip opens |

| System Admin | SECURITY, RULES_OPERATING, RULES_PAY (all) | pay amounts, payroll steps |

"About" on a PAYSLIP_ACCESS row shows the person only to the Director. Rows for the person's own record (A8) are the exception: the person reads rows about themselves in any category except LOG_ACCESS.

At most one alert per person, kind and 15 minutes. **Never** an amount, a code or a payslip figure in the alert.

**Built rules.** The lock-screen text is the Inbox text (`payslipOnUnconfirmedPhone`, no figure, no payslip number). **Review** opens the A8 entry. **Yes, this wasn't me** runs SD14 in one transaction: revoke the person's sessions, set `mustChangePassword` and clear the payslip code (the next opening asks "Choose your code"), mark the device, write `security.wasnt_me` and the alert, notify the System Admin, and sign the phone out. The reset page checks the two fields match (`The two passwords are different.`), at least 8 characters, not the old one; success signs the person in on this phone and asks the phone question again. **No lockout:** the person is never blocked from choosing a password. If pressed by mistake nothing else is lost except sessions and the code. The page says `Your pay was not changed.` only when no payslip was corrected during the window (always true; the sentence is fixed). Accessibility: the numbered list is an ordered list; the alert region reads the red states; the password fields have `autocomplete="new-password"`.

**Developer notes (P). Not UI.** The phone is recognised by a random device id kept in the browser's storage and sent as `x-device-id` on every call (the payslips module already reads it: `unlock/device-source.ts`, seam `setDeviceConfirmationSource`). The server keeps `workforce_devices` (`userId`, `deviceIdHash` (SHA-256), `label` from the user agent such as `Tecno, Android`, `placeLabel` from the coarse IP lookup the audit context already uses, `firstSeenAt`, `lastSeenAt`, `confirmedAt`, `confirmedMode` (`REMEMBER`|`ONCE`), `removedAt`). A missing or unknown id is an unconfirmed phone. Access tokens are short; a removal or `NOT_ME` deletes the person's `RefreshToken` rows and records `tokenNotBefore` on the user so an access token older than that is refused (check at build whether auth already has a version field; add one if not). No raw IP is stored (built rule of the audit context).
