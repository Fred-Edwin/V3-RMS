# Workforce slice 3 (Attendance): back-end decisions

Written 18 Oct 2026 on branch `feat/workforce-3-attendance`. Each row is a question Paper or the brief left open, what was built, why, and what changing it takes. Code: `backend/src/modules/workforce/attendance/`.

## Finding: the legacy lateness report is wrong on production

| | |
|---|---|
| What | `hr-repository.ts` (`getAttendanceSummary`, `getStaffAttendanceDetail`) measures lateness with `new Date(clockIn).setHours(h, m)`, which uses the **server's** time zone. Shift times are Nairobi clock times and production runs in UTC. |
| Evidence | `attendance/lateness/legacy-lateness-finding.test.ts` runs the real legacy function. A 06:20 clock-in for a 06:00 shift: on a Nairobi-zone machine **LATE, 20 minutes** (why it looked right in testing); on a UTC server **PRESENT, 0 minutes late** (the shift is read as 06:00 UTC = 09:00 Nairobi). A 09:20 clock-in on UTC reports 20 minutes late when it is really 200. The new engine returns 20 and 200 in every zone. |
| Effect | On production, anyone who clocks in less than three hours late is never reported late; later ones show the wrong minutes. Both reports (summary and per-person) and the late counts that feed from them are wrong. |
| Recommendation | Do not patch the legacy code silently. Pilot Nyeri Town on the new clock (the new engine is right), and fix the two legacy functions to use the Nairobi helpers in a small separate change if the old reports must stay useful for other branches. Nothing was changed in legacy. |

## Decisions

| # | Question | Choice | Why | What changing it takes |
|---|---|---|---|---|
| A1 | Where does the per-site switch live, and who flips it? | Table `attendance_site_switches` (no row = off). `PUT /workforce/attendance/switch`, capability `attendance.switch` (Director, System Admin). | A site setting is not a rule with versions and confirmations; a plain row is reversible and auditable. The owner pilots one branch, so the Director decides. | Change the grants in `workforce-access.ts`. |
| A2 | What do the legacy clock endpoints do for a switched site? | They answer **409 `CLOCK_MOVED_TO_NEW_ATTENDANCE`** and change nothing. Other sites are untouched. | A clear refusal cannot double-count; delegating would hide which engine holds the event. Switch off and they work again at once. | Replace the guard in `routes/clock-routes.ts`. |
| A3 | How does a clock event written under one engine reach the other? | **On:** today's finished legacy records become `LEGACY` events (unique key makes a rerun add nothing); refused while anyone is still clocked in on the old clock. **Off:** today's new clocks on a carried legacy assignment are **inserted** as legacy records (marked, never carried back). Shifts that exist only in the new rota are listed in `notMirrored`. | Neither engine loses the day, nothing is counted twice, and no legacy row is updated or deleted. | Mirror more days: widen `switch-carry.ts`. |
| A4 | The subject of a clock event | The **employee**, with the rota entry and a stored Nairobi `shift_date`. | A rota edit deletes and recreates entries; the date keeps the event attached to its day. Only people who track time clock. | Schema change. |
| A5 | Which time counts when a phone is offline or wrong? | The tap counts for `server now − (sentAt − deviceAt)`: the delay is measured on the phone's own clock, so a wrong clock cannot change it. A phone clock off by more than the rule (10 min) is **flagged**. Taps older than 12 hours or from the future are refused. | Proposal 5.2: device and server time both stored, never trusted blindly. | `MAX_OFFLINE_DELAY_MINUTES`. |
| A6 | What closes a shift nobody answered? | A once-a-minute sweep closes at the **scheduled end**, flagged `AUTO_OUT`, when the prompt has gone unanswered for the rule's 15 minutes, or when a clock-in is still open after 00:05 Nairobi the next day (forgotten). "Stay on" is left alone until midnight. The head, the Branch Manager and the person are told (log only). | Proposal 5.3. Only switched sites are swept. | `FORGOTTEN_CLOSE_AFTER_MIDNIGHT_MINUTES`, the job schedule. |
| A7 | Is "Finish now" its own call? | No: it is the clock-out. It also stores a `FINISH_NOW` answer when the prompt was showing. "Stay on" is `POST /shift-end` with a reason chip and a 15/30/60 estimate. | One tap fewer, same record. | Add a route. |
| A8 | Undo | Cancels the person's own **newest phone tap** with a voiding correction inside the rule's window (120 s) from when the server received it. A manager's tap, an older tap, or an expired window is refused with words pointing to the manager. | Paper: "nothing is recorded". Nothing is deleted. | Window is the ATTENDANCE rule. |
| A9 | Idempotency | Each tap carries a `clientEventId`; a retry returns the first answer (200). A per-person database lock makes two phones race to one event. | Proposal 5.2. | n/a |
| A10 | Early leave | Before the scheduled end a reason chip is required (`SENT_HOME`, `UNWELL`, `EMERGENCY`, `OTHER`). | Proposal 5.2 and Chapter 6 step 4. | `EARLY_LEAVE_REASONS`. |
| A11 | "Clocked out by mistake" requests to the manager | **Not built** as a request flow: the person is told in words to ask their manager, who uses Fix time. | Request inbox and follow-up belong to slice 4 (approvals). | Slice 4. |
| A12 | Location | Same check as today (radius from the Rules store; null keeps the environment value). No position is refused in plain words. | Behaviour parity for the pilot. | Rule value. |
| A13 | Lateness | Computed from the first clock-in of each rostered shift, in Nairobi time, with the grace as it stood that day. Exposed as data (`GET /lateness`); no excuses, caps or deductions (slice 4). | Brief. | Slice 4. |
| A14 | Today board counts | On shift = in now; Late = clocked in past grace; Not in = shift started, no clock-in; On leave = 0 with `available:false` (slice 5). Departments needing attention come first; healthy ones are `complete`. A past day is judged as it ended. Phone-closed shifts are listed under `attention` until a manager corrects them. | Chapter 7 step 1. | `board-view.ts`. |
| A15 | Who sees the board and acts | `today.read`/`today.act` scopes as in the access table (head: own departments; Branch/Store Manager: own site; HR, Director, System Admin: named site; HR and Director read only). Another branch is 404; a head outside their departments is 403. | Access table, proposal 9. | The table. |
| A16 | Fixing time | New capability `time.fix` (Branch/Store Manager unit, HR and System Admin all). Edit, add or void, always with a reason (3+ characters); a correction row points at the old one; preview shows the day before and after in minutes; nobody fixes their own time; the result must not leave a clock-out with no clock-in. The Director and heads read but do not fix. | Proposal 5.4, Chapter 7 steps 4 to 6. | The table. |
| A17 | Closed pay periods | Hook `setPeriodClosedCheck`; by default no period is ever closed. Once slice 4 registers it, only HR may change a closed day. | Brief: expose the hook, build no timesheets. | Slice 4. |
| A18 | Events table edits | Append-only trigger (update, delete, truncate refused). Only a transaction that sets `workforce.allow_clock_edits` (tests and the proof script) passes; a layering test forbids it in production source. The foreign key may null `rota_entry_id` when a shift is removed from the rota. | Same spirit as the audit log and the stock ledger. | Migration. |
