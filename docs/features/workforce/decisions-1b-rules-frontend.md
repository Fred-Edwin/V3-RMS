# Workforce segment 1B (Rules): front-end decisions

19 October 2026, branch `feat/workforce-1b-rules-frontend`. Choices taken while building the Rules screens against the real back end, beyond or against `specs/1b-rules-spec.md`, `specs/decisions-1b-spec.md` (D1 to D30) and `decisions-1b-rules-backend.md` (B1 to B29). Each row: the question, what was built, why, and what changing it takes. Code: `frontend/features/workforce/rules/`.

| # | Question | Choice | Why | What changing it takes |
|---|---|---|---|---|
| F1 | Who may confirm a waiting pay value (the Confirm button)? The page answer lists `whoCan` roles but not "you". | The button shows when the viewer's role is in the pending item's `whoCan` list (data from the server, not a role name in the screen). | The permissions payload has no `rules.confirm.*` names, and adding them touches the shared capability list another lane edits. | Add `rules.confirm.*` to `_shared/lib/capabilities.ts` and read `can(...)`. |
| F2 | The System Admin reads Rules (D6) but has no Workforce menu. | A second menu row `wf-rules-admin` (Settings group) for the System Admin, and the route gate opens the three Rules routes for the six roles that hold `rules.read`. | Spec section 14: the System Admin reads every tab and changes minimum cover. | Remove the row and the gate line. |
| F3 | Branch budget (Overtime) is per site; Paper shows "Nyeri Town 120 h · Nyeri Highway 90 h" in one value. | The row shows the value of the rule being looked at (company, or the site for a Branch Manager). Sites with their own rule are listed, with their summary, in "Sites that do their own". The dialog's Applies to chooses a site. | The page read carries one site's values; fetching every site's page per load is wasteful. | Add a per-site values list to the page response. |
| F4 | Dialog "Applies to" on rows a site may own. | Shown to a viewer of the company rule: Every site or One site (site picker). A viewer of one site (a Branch Manager, or the Director looking at a site) sees "<Site> only". Branch budget allows both, not only One site. | Spec section 2; budget "Every site" is a valid company default. | Hide Every site for the budget row. |
| F5 | Where does a Director look at one site's own rule? | "Sites that do their own" links each own-rule site (`?tab=lateness&site=<id>`); that view shows the site's values, "Own rule" tags and "Use the company rule again", with a "Back to the company rule" link. | One page serves the Branch Manager and the Director the same way (D20, D21). | A site switcher in the header. |
| F6 | "Use the company rule again": one button or one per row? | One button for all own rows; with two or more own rows, also one per row ("Use the company rule again: grace period"). It opens the same dialog with no rows to set. | Overtime lets a site own single rows (B2). | Drop the per-row buttons. |
| F7 | NEW starts empty or at today's value? | At today's value; Save waits for a difference ("Nothing to change yet"). | One tap to reset; matches Paper's old-to-new block. | Start empty. |
| F8 | The server's earliest day versus Paper's "FROM". | The picker's earliest day is `earliestEffectiveFrom` from the preview; the first value is `defaultEffectiveFrom` (D10). A week-start change that is not on the new weekday is refused by the server and shown as "Pick a Sunday" under the date (the picker cannot hide other weekdays). | The kit's picker has no weekday filter. | Add a weekday filter to `SingleDateField`. |
| F9 | The preview itself says the rule is stale. | The dialog shows the stale notice and reads the tab again, as a refused save does; what was typed is kept. | Otherwise Save stays enabled on a number that is already old. | None. |
| F10 | Retrying a save. | One `idempotencyKey` per (group, body, reason); changing anything makes a new key. A retry after a network failure sends the same key. | B7. | None. |
| F11 | Lock after five wrong PINs. | The PIN box is disabled and Save says "Signing is locked for now"; the words say wait ten minutes or ask the System Admin. | B9 (`429 PIN_LOCKED`). | None. |
| F12 | Signer without a PIN. | The dialog shows the shell's "Set PIN" form in place of the PIN box, then continues. | Same as the kit's PIN dialog. | None. |
| F13 | Cash holder "One named person" (Casual). | Shown, disabled, with "Choosing a named person is not available yet." Switching from a named person to the Branch Manager works. | The people list carries no login id (`userId`) to store; **back-end gap, to batch.** | A people lookup that returns login ids, then a `PersonRadioList` in the editor. |
| F14 | Casual rates are per department, departments belong to sites. | One row per active department, written "Barista · Nyeri Town", from People's lookups. | Rates are keyed by `departmentId` (D16) and department ids are per site. | A company-level department concept. |
| F15 | The casual-threshold warning (not built on the back end). | The Casual tab reads the Statutory tab; if the Accountant has a table "Casual pay threshold" (kind Other) and any rate is above its first band's top, the dashed card becomes "Check with the Accountant". Nothing is shown when there is no such table or the viewer cannot read Statutory. | Spec section 9; never an invented figure. | A named threshold field in Statutory. |
| F16 | "Applies from" per Statutory table (not built on the back end). | Derived on the screen from the history: the first version, walking back from the one in force, where that table has its present content. | D3 note. | Add it to the page response. |
| F17 | Statutory tables as typed. | Three shapes: PAYE (bands typed as widths, the last has no upper limit, Add a band, Remove this band), a flat amount (Personal relief) and one rate (NSSF, SHA, Housing levy, Other). A picker offers which deduction to add; one already set is disabled. | The schema stores from and to; Paper shows widths. | Another shape. |
| F18 | The Statutory "not confirmed" state. | The shell's pending banner (with Confirm for the Accountant) covers it on every tab; the Statutory tab adds only the confirmed and the empty cards. | One place for pending values; no duplicate card. | Add a Statutory-only card. |
| F19 | Overtime multiplier row while a new value waits. | The row keeps showing the old confirmed rate and "Confirmed by Anne Muthoni, Accountant" with the date; the banner says a new one waits for the Accountant, with no figures. The "Waiting for ..." tag only appears when the version in force is the unconfirmed one. | D1 and D2; the server answers per version in force. | None. |
| F20 | Names. | A display name that carries a role in brackets ("Anne Muthoni (Accountant)") is shown as "Anne Muthoni, Accountant" (`plainName`). | D24. | None. |
| F21 | History rows. | Beyond Paper: a second line "Why: <reason>" and, for a withdrawn version, "Withdrawn by Name, Role: reason". The Withdraw card names the newest scheduled version (the only one the server lets be withdrawn; **back-end fix**). | A history that hides the reason is not an audit trail. | Remove the lines. |
| F22 | Withdrawn rows and Version 1's "Told". | A withdrawn version shows "Withdrawn" struck through; "Told" is the tab's audience for every row (the spec's "Everyone, at the start" is not shown: a first change is not the start). | The server returns one audience per tab. | Add a per-version audience. |
| F23 | Minimum cover for a company-wide viewer. | A site chip row above the table (default the first site); the table and the Change dialog act on that site only. "People" counts come from the roster (a dash if it cannot be read). | Spec section 7; minimum cover is per site. | Persist the chosen site in the address. |
| F24 | Leave types. | One dialog for change and add: days (or No limit), builds up, pay, approved by, carry over, sick note after, "a reason is needed". A type is never deleted. | Spec section 7, D18; types are not site-overridable. | Rename or retire support. |
| F25 | Holidays. | A year switch (this year and next); past holidays greyed with "Past" and no Change; Add, Change and Remove (the whole list is sent); a clash with another date is refused client-side with the other holiday's name; the empty year has the dashed card. | F26 | Week and breaks table. | The unpaid breaks are read from the rota's shift templates (`rotaReads.templates`, exported from the rota's `index.ts`), active templates only, read only. | Spec section 13, "read from the rota API". | None. |
