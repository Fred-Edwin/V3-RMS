# Workforce segment 3 (Payslips and casual pay) front end: decisions made without the owner

Written 20 Oct 2026 on branch `feat/workforce-3-payslips-frontend`. Each row is a question Paper or the brief left open, what was built, why, and what changing it takes. Nothing here changes what a pay figure means.

| # | Question | Chosen | Why | To change it |
|---|---|---|---|---|
| 1 | Where do the screens live? The spec says `/app/payslips`. | `/app/workforce/my-payslips` and `/app/workforce/casuals`. The old-payslip card links to `/app/payslips`. | `/app/payslips` is the live old page; the nav table already pointed at the new path. The old page is **kept on purpose** as the fallback for branches not yet switched on, and goes when Payroll switches every branch on. | `routes.ts`, the nav rows, `route-access.ts`. |
| 2 | Where does the code screen sit? | A gate in the section layout: the locked list with the code is the first screen of every deep link. After unlock the home route jumps to the chosen payslip; a deep link stays put. | One place decides, so no page can show pay before the code. | `payslip-gate.tsx`. |
| 3 | First-code setup. | Two inline fields on the code screen, not a dialog. | Fewer steps for a phone. | `code-block.tsx`. |
| 4 | A refused read. | `UNLOCK_REQUIRED` (403) clears the in-memory unlock and returns the screen to the code. The unlock token is memory only, never storage. A reload relocks. | Matches the server's relock; nothing to steal from storage. | `payslip-http.ts`, `unlock-session.ts`. |
| 5 | Device id. | Made once, kept in local storage (per visit if blocked). | The API wants a stable 8 to 64 character id. | `device-id.ts`. |
| 6 | Versions. | Version 1 is asked with `?v=1` always; list and home links omit `v` and follow the newest. Version 1 shows "Replaced by version 2 on 20 Jan" with a link. | Both stay readable. | `routes.ts`. |

| 9 | PDF viewer. | Canvas drawn by pdfjs 4.10.38 (worker from `import.meta.url`), page counter in the viewer, pinch and double tap, plus Zoom out, Fit and Zoom in buttons for keyboard and screen readers. | Paper's pinch is invisible to non-touch users.
