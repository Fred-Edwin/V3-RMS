# Conduct front end: decisions log

Written 20 Oct 2026 during part 1 of the Segment 5 front-end build. Each row: the question, what was chosen, why, and what changing it takes. Letter wording is placeholder text for the lawyer and is never written here: the server renders the letters and this front end shows them as they come.

| # | Question | Choice | Why | What changing it takes |
|---|---|---|---|---|
| 1 | Where does the desk's chosen notice live in the address? | `/app/workforce/conduct?id=` is the one way to name a notice. `/app/workforce/conduct/[id]` redirects to it. | The back end's Inbox links already use `?id=`, and one address means a link, a reload and the Inbox row all land the same way. | Delete the redirect page and give `[id]` its own screen. |
| 2 | The employee file route. | The Conduct tab is on `/app/workforce/employees/[id]?tab=conduct`. | The spec says `people/[id]`, but the file is built at `employees/[id]` (Segment 1A). | None needed; the spec line is stale. |
| 3 | "Selected row" in the shared table. | Added an optional `isRowSelected` prop to `ui2/data-table`. It sets `data-state="selected"` (the Workforce look draws the caramel bar) and `aria-current="true"`. | `DataTable` could not mark a row. The spec says `aria-selected`, but that is only valid on a grid row; `aria-current` is valid on any row. | Remove the prop and the two attributes. |
| 4 | Disabled Final warning in the level control. | `SegmentedControl` items take an optional `disabled`; the arrow keys skip a disabled item. The reason is written beside the control. | The spec disables Final until a written warning is active; the kit had no disabled item. Additive: no existing caller changes. | Remove the field. |
| 5 | The circle stepper. | Built in the kit (`CircleStepper`), exported from `_shared`. | The spec assumed Leave would add it; it was not in the kit when this session started. Leave can use it as is. | Rename or move the file. |
| 6 | `discipline.decide` on the front end. | Added to the capability list. | The back end added the capability; the list is a type. | None. |
| 7 | Who sees the Conduct tab on a file. | `tabsFor(file, { conduct })`: shown when the reader holds `discipline.read`, left out otherwise. Called with nothing, it keeps the old waiting look (so the tests of other callers do not change). | Spec S14: hidden by omission for roles without the capability. | Make the second argument required. |
| 8 | Conduct importing People. | It does not. The Site select reads `/workforce/people/lookups` itself (`conductReads.sites`). | People's file screen imports the Conduct tab; Conduct importing People back would be a cycle. | Export a sites lookup from People and use it. |
| 9 | Navigation rows. | `wf-conduct` drops `notBuilt` and gains `match`. New rows under Me: `wf-my-conduct` ("My notices", the four desk roles), `wf-my-conduct-accountant` ("Conduct"), `wf-staff-conduct` ("Conduct", floor staff and the Store Attendant). The exact-list nav tests now include them. | Spec section 0: every role with `discipline.read_own` gets a link under Me; a person who is both reads "My notices". | Remove the rows and put the lists in the tests back. |
| 10 | The menu badge on the Conduct links. | Not built here. The rows have no `badge`. | The badge machinery belongs to the Shared-parts front end (running in parallel). It needs `GET /conduct/badge` for staff, who have no `needs_you.read`. | Add a badge key for the Conduct rows and feed it from `/conduct/badge` for staff and from the Needs-you counts for managers and HR. |
| 11 | Route gates. | `/app/conduct/*`: every role but the System Admin. `/app/workforce/conduct*`: Branch Manager, Store Manager, HR, Director. | Spec section 12. A department head and the Accountant have no `discipline.read`. | Edit the two rules in `route-access.ts` and its test. |
| 12 | Staff sign screen and the person's code. | Uses the shell's `usePinStatus` and `SetPinForm` when no code is set ("Choose your code" first). A wrong code: field cleared, "That code is not right." A paused code: the seconds to wait, counting down, never anything about being locked. | Spec S5 and the back-end note: paused, never locked. | Different words in `conduct-words.ts`. |
| 13 | Idempotency keys. | One key per open screen or dialog, reused for a retry after a lost answer, renewed after any answer the server gave. | A corrected PIN is a different body; the server may read the same key with a different body as a conflict. | Keep one key for the whole screen. |
| 14 | "No login" for the record dialog. | The desk detail carries no login flag. A notice with a letter and no sign limit (`recordableFrom` null) is the printed route, as the server computes it. | Avoids a second request. | Ask the server for `hasLogin` on the desk detail. |
| 15 | The issue panel's person in the file tab. | The panel opens with the file's person chosen (id, name); the draft call then says whether they have a login and what is on file. | The file has no "issue" person row. | Send the full person from the file endpoint. |
| 16 | Reading the letter before sending. | "Read the letter" opens the server's DRAFT PDF in a new browser tab (the tab is opened in the click so a pop-up blocker lets it through). | Spec S9: a preview stops surprises. The Document view of a draft is a phone screen the spec does not draw. | Show it in a drawer with `PdfViewer`. |
| 17 | Discarding a half-typed notice. | An inline "Discard this notice?" bar inside the panel, never a browser dialog. | The harness forbids browser dialogs; the spec asks for a confirm. | Use a `KitDialog` confirm. |
| 18 | Decision options in Paper are ink-filled cards. | **Decided in part 2:** matched to Paper. The kit's `RadioCards` gained an additive `look="ink"` (no circle, the chosen card fills with ink and white text); the decide dialog uses it. The default look is unchanged for every other caller. | Seen beside Paper's frame 1H7K-0: the circles and warm fill were the one visible difference on that dialog. | Drop the `look` prop and the argument in `decide-dialog.tsx`. |
| 19 | Status reference (spec section 4). | **Decided in part 2: stays a disclosure.** A "What do the statuses mean?" disclosure under the desk list. The popover on every status tag is not built. | One place, readable, keyboard-complete; a tag popover needs the shared table's cells. Logged as a gap, not a defect. | Add a popover to the status words. |
| 20 | Staff notice list paging. | Client-side 25 per page, the shared `TablePager`, shown only past 25 rows. | `GET /conduct/me` returns all notices at once. | Page on the server. |
| 21 | Phone Document view "Read the letter as text". | Not built. | The API sends no text of the letter, only the PDF. | Add a text endpoint, or render the facts and own line. |
| 22 | The Inbox message (S3). | Not built here: the Inbox screen is the Shared parts'. The links the back end writes (`/app/conduct/{id}`, `/app/workforce/conduct?id=`, `/app/conduct/witness/{id}`) all resolve to screens built here. | Brief: the machinery belongs to Shared parts. | None. |
| 23 | Witness card. | Built at `/app/conduct/witness/[id]` in the style of the Sign screen. The witness sees only the two roles, what happened and the date. | The spec lists it as "beyond Paper". | Paper frame when drawn. |
| 24 | HR "Change this notice". | A button on the standard panel when the server says `canChange`; it opens the same dialog titled "Change {Name}'s notice" with no Keep. | Spec C19. | Remove the button. |
| 25 | Overdue appeals. | An amber "Overdue by n days" tag on the appeal panel from `appeal.overdueDays`. | Spec S12. | None. |
| 26 | Refresh when someone else changes a notice. | The detail panel asks again when the tab regains focus, and says "This notice changed a moment ago" when `updatedAt` moved. | No live push for Conduct. | A socket event. |
| 27 | Do the Conduct links show when a branch's new clock is off? | **No.** All four rows (`wf-conduct`, `wf-my-conduct`, `wf-my-conduct-accountant`, `wf-staff-conduct`) carry `needsAttendance`, like the Schedule and Today rows. The pages still open by address, as for the other Workforce pages. | Found in part 2: with the switch off a Branch Manager and every floor-staff role still got new "Conduct" and "My notices" links, which breaks "a branch that is off sees nothing new". Proved in the browser for the barista and through the switch list for the Branch Manager. HR and the Director see them while any branch is on (the same rule as every other row). | Remove the flag from the four rows (and the new nav test). |
| 28 | Where does the desk put the panel beside the list? | Side by side from a 1280 px window; under the list below that. The spec said 1100. | The sidebar leaves 864 px of page at a 1100 window; the 500 px list left the panel about 280 px, too narrow to read. | Put `min-[1100px]` back in `desk-screen.tsx`. |
| 29 | Columns of the desk list inside the 500 px column. | LEVEL 136, ISSUED 64, STATUS 92 px; the person column truncates (`max-w-0`). | At the old widths the table scrolled sideways and clipped STATUS. | Edit the widths in `desk-table.tsx`. |
| 30 | Search box and chips wrap to two lines in the desk list. | Left as the shared table toolbar draws them (240 px search, last chip on a second line). Paper's search is about 190 px and keeps one line. | The toolbar is shared by other screens; a narrower box there is a table-kit decision, not this feature's. | A `searchWidth` option on the shared toolbar. |
| 31 | Staff figure row (the three small figures). | Spacing is 110 px between columns, as Paper draws it (it was 134). | The third figure wrapped onto a second row at 390 wide. | Restore `gap-x-6` in `stat-columns.tsx`. |
| 32 | A wrong PIN's red text after typing again. | The red text and border clear as soon as the digits change (`act.clear()`), on the sign screen, the witness card, the issue panel and the record and decide dialogs. | The old error stayed until the next send, which reads as if the new digits were already wrong. | Remove the `onChange` wrapper in the five places. |
| 33 | Enter in a PIN field. | Enter does not send, by design (rule 09 of the kit). The last digit or the button sends. | Found in the keyboard run; it is the kit's documented rule, not a defect. | Not changeable here. |
| 34 | "0 days to decide" on a decision made the same day. | The record row says "decided the same day". | Reads wrongly for the common case; the server's figure is still used for 1 day or more. | Delete the zero case in `decide-rules.ts`. |
| 35 | Issue panel small print for a person with no login. | Says the person has no login, so is not told on the phone, and that the printed letter is given by hand and recorded. | The old line said they are "told on the phone and asked to sign", which is untrue without a login. | Remove the no-login branch in `issue-rules.ts`. |
| 36 | Witness card first sentence. | "HR told you that a Waiter has no login…" (role with the right article; "HR" stands alone). | It read "A HR told you". | Revert `withArticle` in `witness-card-screen.tsx`. |
| 37 | Offline sign and appeal. | Covered by unit tests of the rules and by the disabled-with-reason line; not run with the network cut in the browser. | The signed notice could not be reopened for signing after the walk. | Run the sign screen with the network off on a fresh notice. |
