# Training issues (found live, 12 Oct 2026)

Logged during the Central Store training. Branch `feat/training-fixes-1` works through them: Phase 1 fixes, Phase 2 Paper frames for the owner, Phase 3 builds what the owner approves.

| # | Where | Who found it | What | Kind | Status |
|---|---|---|---|---|---|
| 1 | Carriers / Dispatch | Owner (Store Manager login) | A carrier is only a vehicle. The person taking items to a branch can also be a staff member (Store Manager, Director, ...). Dispatch needs to let you choose a vehicle carrier or a staff member as the carrier. | Missing feature, needs a short design | Phase 2 (Paper), then Phase 3 |
| 2 | Restock page ("needs restocking") | Owner (Attendant practice) | The page only lists items that are low or out of stock. The Store Manager and Attendant need a way to see all items and buy items that are not low. | Change | **Fixed (Phase 1).** "New order" is a Purchasing sub-link for the Attendant (nav table) and the Restock list has a "Need something that is not low? New order" link. The New order screen now fits 390 px (rows wrap, nothing off screen). It is usable, not designed: a proper phone layout goes in the Paper batch. |
| 5 | New order (desktop) | Owner | Too many clicks per item. | Change, small | **Fixed (Phase 1).** Clicking the quantity box ticks the row and selects the amount; clearing it unticks; Tab goes quantity, price, next row's quantity (checkboxes stay, out of the Tab order). The Store Manager can now type the price in the row (the server already allowed it). |
| 6 | Purchasing, order to a supplier that already has an open order | Owner | An open order blocks a new one to the same supplier. It should not block. | Change, small | **Fixed (Phase 1).** Desktop New order and the Attendant's Review ask "There is already an open order to this supplier. Add another?" (Continue / Cancel). Back end: the server still answers 409 `SUPPLIER_ORDER_OPEN` until the caller sends `allowAnotherOpen: true`; the database index that forbade a second open order is now an ordinary index (migration `20261012120000_purchasing_allow_several_open_orders_per_supplier`, no data touched). |
| 7 | Receiving, "Take a photo" | Owner (phone) | Taking a photo fails with a "low space" message, while "choose from gallery" works. | Bug, to investigate | **Looked at (Phase 1): not our code.** The page opens the camera with a plain `<input type="file" accept="image/*" capture="environment">` (receive-screen and photo-slot), which hands the job to the phone's camera app; "low space" is that app saying the phone has no room to save a new photo, and the gallery works because it only picks an existing file. Nothing in our code resizes or stores the picture first. What to do: free storage on the phone. If it keeps happening on a phone with room, send the model and Chrome version. A possible later improvement (not built): shrink big photos before upload. |
| 8 | Every phone screen with quantity entry | Owner | Too much friction typing quantities on a phone. Convention approved 12 Oct 2026 (see the Phase 3 plan). | Change, medium | Phase 2 audit and Paper, then Phase 3 |
| 9 | Restock list (Attendant) | Owner | The Attendant must be able to set a supplier on an item that says "No supplier yet", from the restock list. | Change, needs a decision on the permission | **Fixed (Phase 1).** New capability `suppliers.link_item` in the central-store access table (Attendant, Store Manager, System Admin). "Set a supplier" opens a list of existing suppliers; it links one with no price, makes it preferred, and writes "added … preferred" to the item's change history under the Attendant's name. Refused if the item already has a supplier. `POST /inventory/items/:itemId/supplier`. |
| 10 | Restock list, Back button (Attendant, phone) | Owner | Tapping Back shows "couldn't load this". | Bug, to investigate | **Fixed (Phase 1), cause not reproduced locally.** Back from the list screens (Restock list, My orders, History, Restock levels) now always goes to Purchasing home instead of walking the browser history, and the Purchasing page no longer shows the desktop tabs (the screen with the "We couldn't load this" card) while the permissions answer is still on its way. Watch for it again in the next training. |
| 11 | Dispatch "carried by" and other inputs | Owner (Android) | A generic list from Android or Chrome appears over the field. | Bug and convention | **Fixed (Phase 1).** Every native `<select>` in Inventory (22) now uses the app's own `Picker` (`components/ui2/picker.tsx`); the `ui2` inputs default to `autoComplete="off"`; `frontend/lib/input-conventions.test.ts` fails the build on a new native select or datalist, and on any new input without `autoComplete`; rule written in `docs/UI_BUILD_RULES.md` §7b. Not done: the older screens outside Inventory (`app/app/**` HR, manage, admin, accountant, director, and `components/orders/`) still have 27 native selects, and 53 existing raw Inventory inputs still lack `autoComplete` (a ratchet records them; the quantity ones are replaced in Phase 3). |
| 12 | All phone inputs | Owner | The phone's own keyboard gets in the way. | Convention | Phase 2 Paper, then Phase 3 |
| 3 | Carrier name | Walk (finding 6) | A stray "··" prefix appears in a carrier name on every screen. | Bug, to confirm in production | **Guarded (Phase 1), cause not found in code.** Nothing in our code adds "··": the characters are inside the stored name (typed or pasted).
