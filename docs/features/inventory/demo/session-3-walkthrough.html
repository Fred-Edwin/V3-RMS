Branch day close — walk it through on localhost

You'll count a branch's five departments, sign the day, reopen it, fix a count and sign again. Each step says what to do and what to look at. Paper artboard ids are beside each screen so you can hold the design next to the page. Tick steps as you go — your ticks are kept in this browser.

0 · Set up

Docker (Postgres + Redis) is already up if you've been working today. Backend and frontend:

cd ~/Projects/V3-RMS
git switch feat/m6-s3-day-close
docker compose up -d postgres redis

# terminal 1 — API (port 4000)
# if it says EADDRINUSE, an API is already running on 4000 — skip this step
cd backend && pnpm dev

# terminal 2 — web (port 3001, matches FRONTEND_ORIGIN)
cd frontend && pnpm dev -- -p 3001

Two things that will trip you. The API rate-limits repeated logins (you'll see "429" toasts) — wait a minute and reload. And the seed below rewrites Nyeri Town's dev dispatch data (it confirms in-transit deliveries, and re-points one at Barista to make it "blocked") — dev database only.

Put the day into a known state with the seed (from backend/), then reload the page:

npx tsx src/scripts/seed-branch-day-dev-fixtures.ts --state=counting   # Kitchen partly counted, Barista blocked
npx tsx src/scripts/seed-branch-day-dev-fixtures.ts --state=ready      # all five counted, ready to sign
npx tsx src/scripts/seed-branch-day-dev-fixtures.ts --state=closed     # signed and closed
npx tsx src/scripts/seed-branch-day-dev-fixtures.ts --state=open       # nothing counted yet

3 · Reopen, fix a count, sign again Paper 19PY-0

select i.name, t.reference, t.quantity, t.reason, r.reference as reverses
from inventory_transactions t
join inventory_items i on i.id = t.inventory_item_id
left join inventory_transactions r on r.id = t.reverses_transaction_id
where t.branch_day_line_id is not null
order by t.created_at, t.reference;
