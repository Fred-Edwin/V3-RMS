# Block 2: Dispatch contract, Amendment 1 (owner approved 9 Oct 2026, "go with your recommendations")

Sources: the contract-in-code summary (52c4352), `docs/sessions/block-2-fe-phone-gaps.md` and `block-2-fe-desktop-gaps.md` (on the front-end branches). Applies on top of `dispatch-contract.md`. Paper wins; **Paper is the design direction**: undrawn pieces are drawn in Paper first (Paper session), then built in the same style.

## 1. Decisions

| # | Topic | Decision |
|---|---|---|
| 1 | **The 2-hour clock** | Runs from the final-sign time (`signedAt`), so a delivery nobody opens still nudges the Branch Manager. `arrivedAt` is separate: stamped the first time anyone from the department opens the delivery (V2), shown only as information ("Arrived 3:28 pm"); before that the card reads "On the way". D19 reads "It left at 3:05 pm. Nobody in Pastry has counted it yet." (a small Paper wording change for the Paper session) |
| 2 | **Leave a department out** | "Go to the final review" works once at least one department is fully ticked. In the review a not-ready department shows "Not ready · stays in To pack" with no action; a fully ticked one has "Leave out" (undo until signed). Leaving out everything is blocked (`NOTHING_TO_SEND`). A left-out department keeps its ticks and quantities and ships later with its own short review and signature; D6 reads "4 of 5 departments sent. Pastry is still to pack." After a cancel (P8) the ticks reset |
| 3 | **Carriers for the Attendant** | P4 returns the active carriers (the Attendant holds no `carriers.read`). Nothing is pre-chosen; the last choice is remembered on the device. No carrier set up: sign is disabled with "No carrier is set up. Ask the Store Manager to add one in Settings." |
| 4 | **Carrier kinds** | `PERSON`, `VEHICLE`, `COMPANY` ("Courier company"). P10 rows add `deliveriesThisMonth` |
| 5 | **Blind count** | `check` runs on "Check and sign"; the second count is final. The check response gives `direction` (`SHORT` or `EXTRA`) per differing line, as Paper D10 draws, never the sent figure. V2 returns each line's saved count and whether the recount was used. Counts autosave; 0 is a valid count, an empty box is not; one shared draft per delivery (last write wins); the second signer gets `ALREADY_CONFIRMED` |
| 6 | **Photos** | A new `DispatchPhoto` table (5 MB, up to 3 per line, not Purchasing's file table). V4's upload gains `lineId`; new `DELETE /deliveries/:id/photos/:photoId`; P6 and Q2 return `photos: [{ id, url }]` through an authenticated URL |
| 7 | **Reversal** | After a reversal the gap is held as unaccounted again and a new finding may be recorded; both entries stay in Activity. `status` goes `REVERSED` then back to `OPEN` (the events keep the history). New code `FINDING_NOT_REVERSIBLE` |
| 8 | **Cancel** | Locks per department (that dispatch only); the other dispatches are untouched. Reason is "preset — note" (chips: Packed the wrong lines, Branch asked us to stop, Vehicle did not leave, Other needs a note). Entry: a "…" menu beside Print on the dispatch file (only holders of `dispatch.cancel`, only while On the way and uncounted) and the same item in the requisition file's department panel. The department is told by its next write getting `DISPATCH_CANCELLED` (no push) |
| 9 | **List tabs** | To pack = approved and not every department signed. On the way = signed, not yet waiting. **To confirm = a department waiting more than 2 hours** (what the Branch Manager acts on). Q1 tabs `open` and `settled` with `counts: { open, settled }` and `departmentId`; a discrepancy whose finding was reversed counts as Open |
| 10 | **Fields added** | P6 and the file: `packedAt`, `countedById`, `countedAt`, `onBehalf`, `arrivedAt`, `lossValue` (gated). V1 rows: reference, department, cycle, line count, `signedAt`, carrier, `arrivedAt`, `confirmedAt`, confirmer's title; and for history `result` (`MATCHED`, `GAP_OPEN`, `GAP_RESOLVED`) with the gap count and a `result` filter. P9: `tab` (`on-the-way`, `done`), `branchId`, and per row a result (`CONFIRMED`, `GAP_FOUND`, `GAP_SETTLED`, `CANCELLED`). V6 returns lines matched, the `DSC-` references and the three times. P5 returns the `DSP-` references with department and line counts, `signedAt`, carrier, signer title; no money. The requisition file (R4) gains `dispatches: [{ id, reference, departmentId, departmentName, status, derivedState, lineCount, signedAt, carrierName }]` and tracker facts (n of m sent, n counted). The permissions call (`GET /inventory/permissions/me`) returns the user's departments and whether head or member |
| 11 | **Idempotency and errors** | `idempotencyKey` on P8, Q4 and Q5 (all PIN-signed). New codes: `ALREADY_CONFIRMED`, `NOT_COUNTED`, `RECOUNT_USED`, `REASON_REQUIRED`, `NOT_YOUR_DEPARTMENT`, `DISPATCH_CANCELLED`, `PHOTO_TOO_LARGE`, `TOO_MANY_PHOTOS`, `ALREADY_SIGNED`, `STOCK_CHANGED` (stock changed under the Attendant; the affected lines are flagged), `DISPATCH_ALREADY_COUNTED`, `CARRIER_NAME_TAKEN`, `FINDING_NOT_REVERSIBLE`. The front ends write the wording from their gap reports' proposals (approved as written); they go into the contract and both mirrors |
| 12 | **Money** | Holders of `requisitions.see_value` (never the Attendant or the branch) see cost columns and loss value (D14, D15 summary for Lost or damaged, Can't tell and Extra unexplained). A branch-side reader of P6 gets no `sentQty`, `gapQty` or value before the department signs |
| 13 | **Names** | Files and notes show "Name · Title"; the cursive signature uses the signer's name. Branch Manager on-behalf stays the Branch Manager alone (the System Admin has no branch): `dispatch-flow.md` is corrected. Members and heads count via the department-membership rule |
| 14 | **Delivery notes** | Print menu: Store copy, Branch copy. The phone's "Print the notes" prints every department's store copy then its branch copy. QR target is the dispatch file link. A cancelled note prints a "VOID · cancelled {date}" band. Multi-page by fixed row height; signature block, received-by line and QR on the last page |
| 15 | **Extra-line wording** | Phone D11: "You counted 26, 24 were sent. The Store Manager will say what happened to the 2 extra." Desktop D15 descriptions follow D15's voice; the front-end sessions write them and list them in their README for the owner's read |
| 16 | **Nav, badges, sockets** | Attendant: one Dispatch row (badge = branches to pack), tabs To pack, On the way, Done. Carriers: a read-only row under Procurement › Settings for the Director, Accountant and Branch Manager; Store Manager and System Admin manage. `inventory:badges` carries `dispatch` and `deliveries` counts; new events `dispatch:changed` and `discrepancy:changed` per record. The amber "Waiting" chip on D1 starts at 20 minutes. Pack and Pack again reuse the phone screens at desktop width (no new drawing). No Inbox rows from this block |
| 17 | **Ledger and audit** | Findings and cancels post as linked entries through the door; back end C adds the `DSC-` reference to the ledger entry the way the door allows (decide and document). Audit sources `DISPATCH` and `DISCREPANCIES` are back end D's |
| 18 | **Lane split (front end)** | Contract session owns `_shared`; desktop owns `dispatch/components/desktop`, `discrepancies/` and carriers; phone owns `dispatch/components/phone` and `deliveries/`; mocks per lane (`dispatch-mock-desktop.ts`, `dispatch-mock-phone.ts`); the orchestrator wires `nav-table.ts`, routes and `features/inventory/index.ts` |
